## Public API

Two entry points: `rou3` (main) and `rou3/compiler`.

```ts
// rou3
createRouter<T>(options?) -> RouterContext<T>
addRoute(ctx, method, path, data?) -> void
removeRoute(ctx, method, path) -> void
findRoute(ctx, method, path, opts?) -> MatchedRoute<T> | undefined
findAllRoutes(ctx, method, path, opts?) -> MatchedRoute<T>[]
routesOverlap(patternA, patternB) -> boolean
compareRoutes(patternA, patternB) -> "disjoint" | "equal" | "superset" | "subset" | "partial"
findOverlappingRoutes(ctx, method, pattern) -> MatchedRoute<T>[]
routeNodeKeys(pattern) -> string[]
routeToRegExp(route) -> RegExp
regExpToRoute(regexp) -> string

// rou3/compiler
compileRouter<T>(router, opts?) -> (method, path) => MatchedRoute<T> | undefined
compileRouterToString(router, functionName?, opts?) -> string
```

## Core Algorithm

**Radix tree** with three node types: **static** (exact match), **param** (`:id`, `*`), **wildcard** (`**`).

### Node structure

```ts
interface Node<T> {
  key: string;
  static?: Record<string, Node<T>>;
  param?: Node<T>;
  wildcard?: Node<T>;
  suffix?: Node<T>; // on a wildcard node: the segments after `**`, last one first
  hasSuffix?: boolean; // on every node on the way to such a wildcard (never cleared)
  hasRegexParam?: boolean;
  methods?: Record<string, MethodData<T>[]>;
}
```

### Lookup priority

1. Static child (exact segment match)
2. Param child (single-segment dynamic)
3. Wildcard (multi-segment catch-all)

... except on paths a route with **segments after `**`** matches, where every match is ranked from the end (see below).

### Segments after `**` (#212)

`/**/_payload.json`, `/blog/**:path/og.png`, `/**/*.png`: the segments after a `**` are matched from the **end** of the path and the `**` takes what is between (zero or more segments, one or more for `**:name`). Before this, `**` was terminal and anything after it was silently dropped (`/a/**/b` ≡ `/a/**`): **breaking**, as is that a mid-route `:x+` / `:x*` (which `expandModifiers` turns into `**:x`) now keeps the segments after it (`/a/:x+/b` requires the `/b`, as in URLPattern).

- **Syntax:** one `**` per route (`_add` throws `rou3: a route can have only one \`**\``, so `/a/:x+/b/:y+` and `/**/**` throw). `splitRoute()` rewrites a segment `**<rest>` (rest not starting with `:`, or with `{` / `}`, which are group syntax before expansion: `/a/**{.md}?` is `/a/**` or `/a/**.md`, and gave it the removal identity of `/a/**/*{.md}?`) into `**` + `*<rest>`, so `/**.md` is `/**/*.md` everywhere (add, remove identity, node keys, overlap, regexp). A `*` after `**` is a **required** single segment (`paramsMap` optional flag `false`; the trailing-`*`-matches-nothing rule does not apply there).
- **Tree:** the suffix segments go into `wildcard.suffix`, a separate trie stored **last segment first** (static/param children only; a separate field so no forward walker misreads it as children). `MethodData.suffix = [wildcard route index, suffix length]`; params after the `**` keep their route index in `paramsMap`/`paramsRegexp` and are mapped to `index - w - 1 + (n - k)` at match time (`getMatchParams`, `collectSuffix`, the compiled `s[l-j]`). `hasSuffix` flags every node from the root to the wildcard's parent so the suffix pre-check can prune; like `hasRegexParam` it is never cleared (cost only).
- **Ranking (`rankFromEnd` in `_suffix.ts`):** the tree order decides at the first segment, so it would let `/blog/**` and `/blog/:slug` beat `/**/_payload.json`, and a broader route beat a narrower one (`/a/:p/**` over `/a/**/x`, `/:a/**/p` over `/**/b/p`). Instead, when a suffix route matches the path (`hasSuffixMatch`, pruned by `hasSuffix`), `findRoute` collects every match with `_findAll(…, reverse = true)` and `rankFromEnd` stable-sorts them comparing **from the last segment backwards**: literal 3 > regex param 2 > plain param or `**`-covered segment 0 (a plain param counts like `**`: with 1 instead, `/**/:y` beat the narrower `/b/**`). `kindAt` returns a covered segment as the `**`'s negative `paramsMap` index (`~start`), so where both sides' `**` cover a position the comparison jumps to the later start: a comparison costs the segments around the `**`, not the path (20 nested `/a…/**` + `/**/end` on a 4000-segment path: 2.8 ms → 0.1 ms; the compiled `RANK` skips the same range). Ties keep tree order; `reverse` flips same-node ties so the last match is the first-registered, as `_selectMatcher` picks. `findAllRoutes` applies the same sort when a suffix route is among its matches. Paths no suffix route matches are untouched (no behavior or perf change for routers without suffix routes). A brute-force sweep (`suffix.test.ts`, "never picks a strictly broader route": every pair/triple of a 24-pattern corpus containing a suffix route × every path ≤ 4 segments) asserts `findRoute` never returns a strict superset of another match, `findAllRoutes` never lists a narrower route before a broader one, and `findRoute` is its last result — 0 violations (tree order alone: ~17.7k; "suffix beats catch-all" only: ~10.9k; plain param = 1: ~9.3k). Known effect, documented in README: the from-end ranking also applies between non-suffix routes on those paths (`/:lang/_payload.json` beats `/blog/:slug` on `/blog/_payload.json` once `/**/_payload.json` exists).
- **Within a suffix trie** (`collectSuffix`): least → most specific = shallower first, then the param child, then the static child; same-node entries by weight (passing regexes + 1 for a `**:name`, which requires `end > start`), ties insertion order (or reversed).
- **Compiler:** `ctx.rank` (the tree has a suffix trie) switches matchAll to `let r=[],k=[]`: every push also pushes a rank descriptor `[** index | -1, suffix length, ...(param index, kind)]` (a deduped data slot), and the end is `return $RANK(r.reverse(),k.reverse(),l-1)` where `RANK` (a data slot: JIT function / AOT source) mirrors `rankFromEnd` and only sorts when a descriptor has a suffix. `compileSuffix` emits a trie from the end (`if(l>c+j&&s[l-j-1]==="x")`, param exprs `s[l-j-1]`, `**` tail `s.slice(c,l-j).join('/')` or `p.slice(K,p.length-B)` for an all-static prefix and suffix, `**:name` guard `l>c+j` counted in the weight). Single-match mode compiles the usual tree **without** suffix tries, preceded by `if(<probe>){let r=[],k=[];<matchAll code, collector mode>;r=$RANK(…);return r[r.length-1]}`: the probe (`compileSuffixProbe` / `compileTrieProbe`) checks the static/param structure down to a suffix trie node with routes for the method (`m===…`, `""` entries always count) whose regex params after the `**` pass (`$N.test(s[l-…])`, so `/**.md` only takes the ranked path on `.md` paths: it used to emit `l>1&&(true)`, ~2.5× on every other lookup), and prunes `false` terms (no probe at all when no suffix trie has routes). It ignores `**:name` guards and prefix regexes, so it may still over-approximate — harmless, since without a suffix match `RANK` leaves the tree order and the last match is the tree order's pick (pinned in `suffix.test.ts` "compiled single-match ranks only where a suffix route can match"). Collector mode (`ctx.collector`) skips the matchAll tie pre-reverse (mirrors `reverse`). Routers without suffix routes compile byte-identically (snapshots unchanged).
- **Remove:** `_remove` walks the suffix trie back from the last segment (`_removeSuffix`) and prunes empty trie nodes, then `wildcard.suffix`, then the wildcard (`_isEmptyNode` counts `suffix`). Identity = the full rewritten join (`/a/**/b`), so `/a/**/b` no longer removes `/a/**`.
- **`routeNodeKeys`:** suffix trie nodes key as `prefix/**` + the suffix (`/**:p/og.png` → `/**/og.png`, `/**.md` → `/**/*`).
- **Overlap:** `RouteShape.suffix` (see "Pattern overlap").
- **`routeToRegExp`** emits them exactly (see "Regex ≡ router" → "Segments after `**`"), and throws the same `rou3: a route can have only one \`**\`` error as `addRoute` for a second catch-all. **Types:** `ExtractWildcards` scans left to right (`**:name` stops at `/`, captures after `**` count, `**<rest>` adds a `*` unless `<rest>` starts with a group's `}`); a trailing `*` is optional only when the route has no `**` and no `:name+` before the last segment (`HasRepeatParam`: a static segment ending in `+`, `/c++/*`, is not one).

**Removal** (`removeRoute`) splices `MethodData` entries by the **registration identity** `addRoute` stamps on them (`MethodData.route`), never by deleting the whole `methods[method]` bucket — same-node siblings (`/a/:id` vs `/a/:userId`, `/a/**` vs `/a/**:rest`, `/a/:id` vs `/a/:n(\d+)`) used to be dropped together (#201). The identity is derived in `_add` (`add.ts`) and mirrored by `_removeRoute`/`_remove` (`remove.ts`): a plain pattern's identity is its **rewritten segment join** (static keys post-`segmentKey`, segments after a `**` included) — the same string `ctx.static` is keyed by (one `join` per entry, no extra parse) — so spellings the tree can't distinguish (`/a/` ≡ `/a`, `\)` ≡ `)`, `/**.md` ≡ `/**/*.md`) remove each other; a pattern that **expands** (groups, `?`/`+`/`*` modifiers) stamps its pre-expansion text on every entry, normalized by `expandedRouteId()` (`_utils.ts`: trailing empties dropped, static segments keyed via `segmentKey`) so `/a/:x?/` ≡ `/a/:x?` and `\)/:x?` ≡ `)/:x?` there too. Keeping the pre-expansion text means the `/admin` entry of `/admin/:page?` never collides with a separately registered `/admin` on the same node (a per-expansion identity spliced whichever came first). Removal takes out *every* entry with that identity (duplicate registrations go together, as before), and an emptied static node deletes its `ctx.static` key in O(1) via the join accumulated during the walk (a value scan of `ctx.static` made bulk teardown O(N²)). Removal is therefore **by registered pattern** (breaking vs ≤0.9.2): `/x/*` no longer removes `/x/:id`, `/ab` no longer removes `/a{b}`, and `:id(\d+)` vs `:x(\d+)` are distinct even though `compareRoutes` calls them equal. Pinned in `router.test.ts` "Router remove". Known residual: `Node.hasRegexParam` is never cleared after the last regex sibling leaves (cost-only — `findAllRoutes` keeps running the regex loop on that node).

**Same-node siblings** (multiple routes sharing one node's `methods[method]` array) resolve by one shared model in all three matchers (`_selectMatcher` in find.ts, `pushSorted` in find-all.ts, the compiled matcher): the highest specificity weight among **fully-matching** entries wins, ties go to the first-registered. Weight = one point per passing regex-constrained param + one for a required last param on a dynamic (param/wildcard) terminal. An entry whose regex fails is skipped — lookup falls through to less specific siblings, other node kinds, or the optional end-of-path fallback, never aborting (the old per-level greedy regex filter made `findRoute` miss routes that `findAllRoutes` found). Out-of-bounds `segments[i]` reads (`undefined`) must never coerce into a literal `"undefined"` static key — guard with `index < segments.length` before any `node.static[...]` lookup. Both pinned in `find.test.ts` "same-node sibling selection" and `find-all.test.ts` "out-of-bounds segment". `_selectMatcher` keeps a single-sibling/no-regex fast path — lookup perf is at parity with the pre-selection code; keep it when editing.

### `findAllRoutes` result ordering

Results are ordered **least → most specific**, and the interpreter (`findAllRoutes`) and compiled `matchAll` must agree exactly (`test/find-all.test.ts` asserts `toEqual`). This is a **public contract**, documented in README ("Result ordering") and pinned by `test/find-all.test.ts` (`matcher: ordering contract` ties result order to `compareRoutes` subsumption order) — changing it is a breaking change. On paths a route with segments after `**` matches, the tree order below is re-sorted by `rankFromEnd` (see "Segments after `**`"). Two levels:

- **Across node kinds:** tree traversal order (wildcard → param → static → self) yields general → specific.
- **Same-node siblings** (multiple routes sharing one param/wildcard node, i.e. one `methods[method]` array): ordered by **specificity weight ascending**, with **insertion order preserved on ties** (#187). Weight = one point per regex-constrained param + one for a required last param on a *dynamic* terminal (param/wildcard node; static terminals don't distinguish required from optional — mirrors the compiler's `hasLastOptionalParam`/`currentIdx === -1` gating). `pushSorted()` in `find-all.ts` sorts each pushed array (stable `Array#sort`); the compiler reaches the same order by sorting matchers **descending** by weight, emitting `r.push(...)`, and reversing `r` **once at return** (`return r.reverse()` — the final array is the reverse of emit order; per-match `unshift` was O(n) each). In matchAll mode the matcher list is pre-`.reverse()`-d so equal-weight siblings keep insertion order despite the final reverse. Single-match mode must **not** pre-reverse: first `return` wins there, so ties stay in insertion order to match `findRoute` (duplicate registrations resolve to the first-registered entry; an unconditional pre-reverse used to flip this). The weight models (`pushSorted`, `_selectMatcher` in find.ts, and the compiled emission) must order each node's siblings identically; the absolute values may differ by a per-node constant — when **no** sibling has an optional last param, the compiler skips the widened end-of-path check and its per-matcher `l>c` conditions entirely (`hasOptionalLastParam()` gate), shifting every sibling's condition count down by one uniformly. Insertion order and weight order coincided before #187, which masked the divergence.

**Carve-out: optional syntax breaks pattern-level subsumption consistency (known, documented, not a bug to "fix").** `findAllRoutes` orders **tree entries** (post-`expandModifiers`, single-shape routes); `compareRoutes` compares **patterns** (the union of all their expansions). A pattern with `:name?` / `:name*` / `{...}?` registers several entries, and the expansion that makes the pattern the broader one often does not participate in the match at all — so **no node-local weight function can observe it**. `compareRoutes` is correct here and must not be changed (e.g. `/api/*/:path*` really does match `/api` — dropping `:path*` leaves a trailing bare `*`, zero-or-one — while `/api/*/**` does not, so `compareRoutes("/api/*/**", "/api/*/:path*") === "subset"` is true). A sweep over 61 patterns × 13 paths × both registration orders found 354 order-vs-containment violations and **every one** required the superset pattern to be multi-expansion; registering each expansion individually removes them all. `:x+`, `**`, `**:rest`, `*`, regex params and static routes never violate on their own, interpreter vs compiled `matchAll` never diverged (that contract is intact), and `findRoute` is unaffected. Three classes, pinned as known-divergent in `test/find-all.test.ts` (`matcher: ordering contract: optional-syntax carve-out`) and documented in README ("Result ordering" carve-out):

- **A1** — an expansion is byte-identical to the other route, so the stable sort is a no-op and **registration order decides** (`/admin` vs `/admin/:page?` on `/admin`).
- **A2** — same node, the optional pattern's *matched* entry is strictly narrower, so it sorts last (`/api/*/:path*` ⊇ `/api/*/**` on `/api/v1/x`) — wrong in both registration orders.
- **A3** — the matched entries live in different nodes and traversal order decides (`/p/:id/:id*` ⊇ `/p/:id/*` on `/p/a`) — wrong in both registration orders.

A1/A2 (same-node) are fixable by recording a per-pattern breadth rank at `addRoute` time and feeding it into the sibling weight; **A3 is not** — cross-node order is fixed by traversal, so a partial fix would not close the gap. A full fix means globally re-sorting the result set against a partial order (`compareRoutes`) after collection: a behavior + perf change, i.e. a major-version design change. Do not touch the weight functions expecting them to help.

### Compiler

`compileRouter()` generates an optimized function via `new Function()`:

- **Static routes** dispatch is hybrid (`STATIC_CHAIN_MAX = 8`): up to 8 static paths emit an `else if` chain of `p === "..."` compares — faster there because repeated/interned path strings compare near pointer-speed and dynamic requests miss the chain via cheap length checks (an unconditional map cost the bench set ~1.3×). Above 8 they emit a single null-prototype map lookup (`{path: {method: data}}`, matchAll: `{path: {method: data[]}}`) held in a `$N` data slot — O(1) vs the chain's O(N) (map is ~2-3× faster at 20-50 routes with fresh per-request strings, ~6× at 50 interned). Method miss falls through to the tree lookup, mirroring the interpreter's `ctx.static` fast path. Both map levels are null-proto so `__proto__`/`constructor` path or method strings can't match (pinned in `find.test.ts` "prototype-key lookups" and "many static routes", which covers the >8 map codegen incl. duplicates and matchAll). Lookup ignores **one** trailing slash only (#209), which the prologue already strips, so both modes compare the stripped `p` once — no secondary `…/` chain or `p.slice(0,-1)` retry (those existed only for the old two-slash rule). Root is keyed `""` in both `ctx.static` and the dispatch, so `"//"` (stripped to `"/"`) can't reach it. Pinned in `find.test.ts` "at most one trailing slash is ignored (#209)".
- Unrolls segment checks into `split("/")`-based array access
- **Tree static siblings** dispatch is hybrid too (`SEGMENT_CHAIN_MAX = 32`): up to 32 static children of one node emit an `else if(s[i]==="...")` chain; above that a hoisted null-proto `{segment: index}` map + dense integer `switch` — O(1) vs the chain's O(N) scan (measured crossover ~40 siblings; switch ~1.4× faster at 64, ~2× at 200 where the chain degrades to interpreter speed). The switch **must** keep its `l>i` bound check even after an `else`: an out-of-bounds `s[i]` is `undefined`, which the map lookup would coerce to the key `"undefined"` (the chain's `===` was immune). AOT map emission uses a computed key for a literal `__proto__` segment (a plain `"__proto__":` property in an object literal would set the prototype). Pinned in `find.test.ts` "wide static fan-out".
- **`__proto__` object-literal keys** go through `propKey()`: it emits `["__proto__"]` for that one name and a plain `JSON.stringify` key for every other (so ordinary routes' codegen is byte-identical). Used by the AOT segment map **and** every `params:{…}` emission site (plain/optional/repeat param names, `**:name` tails, and both `scanRegExpGroups` branches — whole-segment `.test()` and `.groups.<name>` reads); a route param named `__proto__` used to hit the prototype setter and silently vanish from the compiled result while the interpreter (null-proto params object) returned it. The `..._normalizeGroups()` spread fallback needs no guard (spread creates own data properties). Pinned in `find.test.ts` "__proto__ param names".
- **End-of-path widening** (`l===c||l===c-1` + per-matcher `l>c` guards, the `/x` matches `/x/*` rule) is emitted only when some matcher at the param node actually has an optional last param (`hasOptionalLastParam()`); all-required nodes (plain `:id`, the common case) get a single `l===c`. Gating on `node.key === "*"` alone used to emit a dead widened branch for every required-only param node and for static nodes of escaped `\*` segments.
- **Method keys are `JSON.stringify`-ed** into `m===` compares — methods are user input; a raw quote was a SyntaxError in JIT mode and code injection in AOT output (pinned in `find.test.ts` "unusual method names").
- **JIT data slots are function parameters** (`$N`, ~10% faster per access than array reads) up to `DATA_ARGS_MAX = 32_000`; above that `compileRouter` recompiles with a single array argument (`$[N]`) to stay under the engine's 65535 formal-parameter/spread-call limits (pinned in `find.test.ts` "data slots above the argument limit").
- **Wildcard tails** with an all-static prefix compile to `p.slice(K)` at a constant byte offset (O(1) substring view, ~4.5× faster per match) instead of `s.slice(i).join('/')` (`compileNode` threads `staticPrefixLen`; a param segment resets it to -1 and falls back to slice/join). Valid because the split prologue keeps every segment of `p` (no trailing-empty pop since #209), so both forms read the same characters. Doubled-slash edge cases are pinned in `find.test.ts` "wildcard tail extraction".
- **matchAll** accumulates with `r.push(...)` + a single `return r.reverse()` (final array = reverse of emit order — identical to the old per-match `unshift`, without the O(n) shifts).
- `serializeData()` dedupes `$N` data slots via a `Map` (`ctx.dataMap`), not `Array#indexOf` (compile-time O(N²) on large routers).
- **Regex params** are resolved at compile time by `scanRegExpGroups()` (escape- and character-class-aware source scan): group names — including user named groups embedded in constraint bodies — are emitted as direct `params:{name:_mN.groups.name}` reads with the `__rou3_unnamed_N` → `"N"` renaming done at compile time, and the regex runs **once** (`(_mN=re.exec(seg))!==null` in the condition). A whole-segment group (`^(?<name>...)$`, the common `:id(\d+)` shape) skips `exec()` entirely: `.test()` + `params:{name:seg}` (the anchored group always equals the segment). Unparseable group names (e.g. unicode) fall back to the legacy exec + `{...spread}` + runtime `_normalizeGroups` path (also single-exec now, via a `_mN` temp). This is ~3.6× faster end-to-end on regex routes than the old always-spread emission (the `.groups` spread + runtime renaming dominated, not the double exec). `_mN` temps are declared next to `let s=...` via `ctx.regexTemps`. Regexes live in `$N` **data slots** (`serializeRegExp()`, deduped by source in `ctx.regexpMap` — separate from `dataMap` so a regex can't collide with an equal-looking string data value; JIT passes the RegExp object, AOT emits its literal): an inline literal would allocate a fresh RegExp per evaluation (ES2015+ semantics), measured ~2-6% per match.
- Compare interpreter vs compiled output in tests

### URLPattern group delimiters

- `src/_group-delimiters.ts` expands non-capturing group delimiters before route insertion/removal/regexp generation.
- Supported forms: `{...}` and `{...}?` (plus single-segment `{...}+` / `{...}*` converted to `(?:...)+/*` regex fragments).
- Limitation: `{...}+` / `{...}*` are rejected when group body contains `/` (cross-segment repetition unsupported in radix tree).
- **Regexp inlining (`routeToRegExp` only):** the radix tree still expands `{...}?` into two full routes (add/remove need that), but `routeToRegExp()` compiles a *trailing single* optional group inline as `(?:...)?` via `inlineOptionalGroup()` in `regexp.ts`, instead of OR-joining two full-route regexes. This avoids re-emitting params before the group in both branches — the duplicate named groups (`(?<id>…)|(?<id>…)`) that PCRE2-family engines reject. It handles the mid-segment case (`/book{s}?` → `^\/book(?:s)?\/?$`, `/blog/:id(\d+){-:title}?` → `…(?<id>\d+)(?:-(?<title>…))?…`) and the cross-segment case (`/foo{/bar}?` → `^\/foo(?:\/bar)?\/?$`); it falls back to alternation (old behavior) for multi-group routes, mid-route optionals (non-empty `suf`), unexpected segment shapes, **or a mid-segment optional following a greedy open-ended capture** (`/media/*{.webp}?` — inlining would let `[^/]*` swallow `.webp` and change the captured value, so it stays as alternation), or a route that needs router-order expansion (`/docs/{v2}?/:page?`, see "Regex ≡ router"); those two are the only fixtures that still emit duplicate names. A group that adds nothing to its segment or only optional segments (`/a{/:x*}?` ≡ `/a/:x*`) is emitted without a wrapper of its own. The group scanner (`scanFirstGroup()`) is shared: it lives in `_group-delimiters.ts` (already in the core bundle via add/remove) and is used by both `expandGroupDelimiters()` and `inlineOptionalGroup()`, so the two paths classify groups identically. It returns a `[pre, body, suf, mod]` **tuple** (not an object) to avoid enlarging the size-budgeted core bundle.

### URLPattern backslash escaping

Two separate escape systems handle `\x` in route patterns:

1. **Router escape encoding** (`_utils.ts`): `encodeEscapes()` converts `\:`, `\(`, `\)`, `\{`, `\}` to `\uFFFD` + single-char placeholders (A-E) before segment splitting, preventing these chars from being interpreted as route syntax. `decodeEscaped()` converts them back for static node keys. Other `\x` (like `\*`) are left for existing `segment === "\\*"` handling.

2. **Regex escape handling** (`_escape.ts`): `replaceEscapesOutsideGroups()` replaces `\x` outside `(...)` groups with `\uFFFE` placeholder, preserving regex syntax inside groups (e.g., `\d` in `(\d+)`). `resolveEscapePlaceholders()` then converts placeholders to regex-safe literals. Used by `routeToRegExp()` and `getParamRegexp()` in `add.ts`.

Key invariant: `\uFFFD` (U+FFFD) is used for router-level escaping, `\uFFFE` (U+FFFE) for regex-level escaping — they must not collide.

Perf: `addRoute`'s pre-processing helpers each bail out early when the input lacks their trigger char — `encodeEscapes` (`\`), `decodeEscaped` (`\uFFFD`), `expandGroupDelimiters` (`{`), `expandModifiers` (trailing `?`/`+`/`*` charCode check). Plain routes skip all the regex/scanner machinery (~2x faster add); keep the guards when editing these helpers.

### Regex ≡ router (`routeToRegExp` exactness, #200)

`routeToRegExp(p).test(path)` must agree with `findRoute(router_with_only_p, "", path) !== undefined` — consumers use the regex as a guard/scope check (h3 v2 `use(route, mw)` inherited an auth bypass from an under-match), so the regex mirrors the **trie's** tolerances rather than URLPattern's. Pinned by the property sweep in `test/regexp.test.ts` ("matches exactly the paths findRoute matches"), the capture sweep ("captures what findRoute captures") and the `_regexp-cases.ts` fixtures; the 7 `/foo/`-style WPT cases moved from `ROUTER_KNOWN_DIFFS` to `KNOWN_DIFFS` accordingly. The rules:

- **Trailing slash:** lookup strips at most one trailing `/` (#209), so a path matches iff the body matches it with one trailing `/` stripped; when the body match ends in `/` (a real empty last segment, `/a//` → `/a/:x` with `x: ""`) exactly one more must follow. Root `/` is `^\/$` (`//` is an empty segment). The general encoding is the fixed-length look-behind suffix `(?:(?<=\/)\/|(?<!\/)\/?)$` (JS/PCRE/Perl; RE2, Go and Rust `regex` reject it). `withTrailingSlash(body, starStar)` (`src/_trailing-slash.ts`; its JSDoc is the spec, including the proofs) rewrites the route's **ending** look-behind free wherever it can. The ending is the last segment plus the optional groups `(?:/…)?` after it, nested ones included: `parseLevel()` (`_regexp-scan.ts`) splits a level into `[prefix, last, groups]` by tokenizing the emitted body with JS regex syntax (classes and escapes are atoms; `[]` / `[^]` close immediately, unlike PCRE), and the analysis recurses into the last group. `canBeEmpty()` is a `RegExp` probe (user constraints need it). The endings:
  - **Open** (`openEnding`: body + `\/?$`): exact when the only parts that can be empty are a group's first segment (`:x?`, `*`, `:x*`, `**`: without its slash the group is skipped) and a trailing catch-all. Groups are rebuilt innermost-out; each empty-capable one is made lazy `??` so captures follow the router (`/a/` leaves `x` unset, `/a//` gives `""`), which never shifts a value because a nested group is only taken with the ones around it. A group that can't be empty has one parse and stays greedy, and so does a bare `**`'s (the router reports `**` as `""` on `/a/`). `/path/:id?` → `^\/path(?:\/(?<id>[^/]*))??\/?$`, `/path{/sub/**}?` → `^\/path(?:\/sub(?:\/(?<_>(?:[\s\S]*[^/])?\/*?))?)?\/?$`.
  - **Closed** (`closedEnding`: rule built in, then `$`): a required last segment that can be empty (a whole `:x` or `*`, `**:x`, `:x+`, or an empty segment), at the top or after a separator inside a group, followed by at most one optional group (nested ones inside it are fine). The path must not stop right after the segment's separator, so the segment splits into a non-empty branch and a slash-only one: `(?:(?<x>[^/]+)\/?|\/)` at the end, `(?:\/|(?<x>SOME_TAIL)\/?)` for a catch-all, and `(?:(?<x>[^/]+)(?:\/|$)|\/)` before optionals, which follow without their leading slash (`$` inside an alternation is an anchor, which RE2 has, not a look-around). An empty segment is just `\/` + the optionals; a group that needs a closed ending is emitted as `(?:\/(?:C)?)?`. `/path/:param` → `^\/path\/(?:(?<param>[^/]+)\/?|\/)$`, `/users/:id/:tab?` → `^\/users\/(?:(?<id>[^/]+)(?:\/|$)|\/)(?:(?<tab>[^/]*)\/?)??$`, `/a//*` → `^\/a\/\/(?:(?<_0>[^/]*)\/?)??$`, `/path{/sub/:id}?` → `^\/path(?:\/(?:sub\/(?:(?<id>[^/]+)\/?|\/))?)?$`.
  - **Root:** `/**` → `^\/?(?<_>(?:[\s\S]*[^/])?\/*?)\/?$`; `/:x*` → `^(?:\/?(?<x>(?:[\s\S]*[^/])?\/*?))??\/?$` (unset on `/`, where the router takes the route without it); `/**:x` / `/:x+` → `^\/(?:\/|(?<x>(?:[\s\S]*[^/]|\/)\/*?)\/?)$`.
  - **Catch-all tails:** a trailing catch-all's `[\s\S]*` becomes `ANY_TAIL` `(?:[\s\S]*[^/])?\/*?` (may be empty: `**`, `:x*`) or `SOME_TAIL` `(?:[\s\S]*[^/]|\/)\/*?` (non-empty: `**:x`, `:x+`; a `//` tail gives `/`). They match the same strings minus one trailing slash left for the `\/?`, so the capture never holds the stripped slash (`/a/b/` → `b`, `/a/b//` → `b/`), and they are greedy up to the last non-slash char, lazy only over the trailing-slash run. A trailing user `(.*)` constraint keeps its JS `.` (the router runs constraints in JS: no line terminators, and `[^/]` would admit one as the last char), so `tails()` gives it lazy `.*?` / `.+?` instead: `/path/(.*)` → `^\/path\/(?:\/|(?<_0>.+?)\/?)$`, `/path/:x(.*)?` → `^\/path(?:\/(?<x>.*?))??\/?$`.
  - **`starStar`:** `routeToRegExpSegments` returns `[segments, ownSeparator, starStar]`, and `starStar` (the route ends in a bare `**`) keeps `**`'s group greedy and selects the root `/**` form. The `(?<_>` name can't decide it: a param named `_` must stay lazy, since the router leaves `/a/:_?` / `/a/:_*` unset on `/a/` and `/:_?` / `/:_*` on `/` (an earlier version of the ending keyed on the name and captured `_: ""` there). `inlineOptionalGroup` passes `starStar && !optional`: `/a{/**}?` also registers `/a`, which wins on `/a/`, so its group is lazy like `:_*`'s.
  - **Nesting:** after a whole-segment `:x?` / `*`, later optionals nest inside its group (the `nest` counter in `routeToRegExpSegments`). Of the router's expansions of `/a/:x?/:y?`, `/a/:y` matches no path `/a/:x` doesn't, so `^\/a(?:\/(?<x>[^/]*)(?:\/(?<y>[^/]*))??)??\/?$` matches the same paths and leaves a single optional group at the end. Both forms give a lone segment to `x`, as the router does unless `/a/:y` wins it (a `*` or a constrained `:y`; a `KNOWN_CAPTURE_DIFFS` class, same on main). An inline `{…}?` holding only optional segments compiles like them (`isOptionalGroups`: `/path{/:rest*}?` ≡ `/path/:rest*`).
  - **Look-behind fallbacks** (everything else; `LOOKBEHIND_ROUTES` has 4 fixtures, asserted both ways, and `SWEEP_LOOKBEHIND_PATTERNS` 18 of the 355 sweep patterns, asserted exact): (1) a part other than a trailing catch-all whose match can end in `/` (`:x(.+)`, `:x([^.]+)`, `:x(\S+)?`): any rewritten ending would let it take the stripped slash (`/files/:name([^.]+)` matched `/files//` with `name: "/"` and captured `report/` on `/files/report/`), so this one must keep the look-behind. `canEndInSlash()` decides it with a conservative scan (a `false` is a proof; backreferences and anything it can't parse count as ending in `/`); only the end of a match matters, so `.+\.zip`, `\d+`, `\w+`, `[a-z0-9-]+` stay look-behind free. (2) A required last segment whose constraint can match empty (`/path/:id(\d*)`, `/a/:x(\d*)/:y?`): a closed ending needs its non-empty form, and deriving that from an arbitrary regex is not implemented (it would otherwise need a look-ahead). (3) Optional siblings where an earlier one can be empty and a later one can't nest in it (`/a/:x(\d*)?/:y?`, `/a/:x?{/b/c}?`): making the earlier one lazy shifts values into later groups, and nesting drops paths. (4) Optional siblings after a required last segment that can be empty (`/a/:x/:y(\d+)?/:z?`): a closed ending with a `(?:…(?:\/|$))?` per group is possible but not implemented. (5) A required catch-all right before optional segments (`/a/**:r/:y?`, `/a/:x+/:y?`): where the optional one is absent the catch-all takes a single segment, so its group is lazy and can end in `/`; the closed form would need `r` in two alternatives (a duplicate name) to reject `/a/`. (6) A segment that can be empty right before a lazy catch-all followed by optionals only (`/a/:p/**/:n(\d+)?`, `/a//**/…`, `/*/**/…`): the plain `/?$` of `openTail` would let the stripped slash end it (`/a/` matched with `p: ""`), and the head is not rewritten. (7) An inline group after a catch-all and an optional segment that can be empty (`/a/**/:y?{/b}?`, `/a/**/{/b}?`).
- **Capture trade-off (inherent):** a closed ending's slash-only branch leaves the group **unset** where the router reports `""`: on an empty last segment (`/a//` for `/a/:x`, `/base//` for `/base/**:path`) and mid-path when optionals follow (`/a//b` for `/a/:x/:y?`: router `x: ""`, regex unset). No regex without look-around, backreferences or duplicate group names can do better (proof in the `withTrailingSlash` JSDoc), and RE2 has none of the three. The capture sweep accepts exactly this via `isRequiredSegmentGap()` (group unset, router `""`, key ≠ `_`, and for some empty segment of the path the route can end right after it with that key: cut there and filled in, `/a/z` routes with `key: "z"`, or, since segments after a `**` count from the end, filled in with the rest kept: `/**/:x/:y?` on `/a///` → `/a/z//`); every other difference must be listed in `KNOWN_CAPTURE_DIFFS` (see Testing).
- **Line terminators:** catch-alls (`**`, `**:x`, `:x+`, `:x*`) are built on `[\s\S]` (`ANY` in `regexp.ts`), not `.`: the router splits on `/` only, while a JS `.` excludes `\n`, `\r`, U+2028 and U+2029 (PCRE and RE2 exclude `\n`), so `/admin/**:p` missed `/admin/x\ry` (an under-match, i.e. a guard bypass). A `.` the user writes inside a constraint keeps its meaning, as in the router.
- **Perf** (Node 24 / V8): matching stays linear in the path length (measured at 4K/16K/64K). Catch-all tails are greedy (`ANY_TAIL` / `SOME_TAIL`) and step lazily only through a run of trailing slashes: that per-slash cost is the price of no look-behind (`/api/**` on `/api/a` + 1,000 `/`: ~4.5 µs vs ~0.5 µs on main). Keep them greedy: the earlier `.*?` / `.+?` catch-all endings were 2-4× slower on short paths and 7-8× on 16 KB (f43878f). The lazy ending of a user `(.*)` constraint is ~3× slower than main on a 16 KB segment; other shapes are at parity or faster (`[\s\S]*` catch-alls ~2× on 16 KB, misses on routes with optional segments 2-6×).
- **Whole-segment `:name` → `[^/]*`** (the param node takes `""`: `/a//b` reaches `/a/:x/b`); inside a mixed segment it stays `[^/]+` (mirrors `getParamRegexp`). `:name?` likewise.
- **Trailing `*` is optional** (`(?:/(?<_N>[^/]*))?`, lazy after the ending rewrite), also when only `?`/`*`-modified segments follow it.
- **`**:name` / `:name+` → `/(?<n>[\s\S]*)`** before the ending rewrite (required separator, segments may be empty); `.+` let `/a//` match with `n="/"`.
- **Segments after `**`** (`/**/_payload.json`, `/**.md` ≡ `/**/*.md`, `/a/:x+/b` ≡ `/a/**:x/b`) follow the catch-all in the regex (`pushCatchAll` in `routeToRegExpSegments`), so they take the end of the path and the catch-all what is between: `**` → `(?:/(?<_>[\s\S]*))?` after a prefix (the separator stays with it: `/a/**/b` must not match `/ab`), `/?(?<_>[\s\S]*)` at the root (the leading slash doubles as the separator, so `_` is `""` on `/b` like the router); `**:x` / `:x+` → `/(?<x>[\s\S]*)`; a mid-route `:x*` → lazy `(?:/(?<x>[\s\S]*))??` (the route it also registers without `x` leaves it unset; with optionals after it, it picks like `**`, below). A `:x*` followed by a `*` that is optional in the route without it (`/a/:x*/b/*` also registers `/a/b/*`, which matches `/a/b`) expands like the router (`needsModifierExpansion`, an alternation with duplicate names): inline, the `*` after the catch-all is required and `/a/b` was an under-match. The suffix segments can't contain `/`, so the split is unique and the endings are the usual ones on the last segment (`parseLevel` ignores the head, where the catch-all sits: `/**/:file` gets the closed ending). A `*` after a catch-all is required (`catchAll` flag). `oneCatchAll()` throws `addRoute`'s `rou3: a route can have only one \`**\`` on a second one (`/**/**`, `/a/:x+/b/:y+`). **Optionals after the catch-all** make the router pick between the routes with and without them by ranking from the end. For **one** optional that is a static property of the route: `lazyCatchAll()` compares the segment kinds (literal 3 > regex 2 > param/`**` 0, ties to the longer route) and makes the catch-all lazy (`[\s\S]*?`, group `??`) where the router prefers the optional segment (`/a/**/:n(\d+)?` gives `/a/b/1` to `n`), greedy otherwise (`/**/b/:y?` keeps `/b/b` for `**`). With **several**, the router's pick among the 3+ routes is not something one lazy/greedy catch-all can mirror (`/docs/**/:page?/:lang(en|fr)?` on `/docs/en`: the route with `lang` alone wins, which the nested groups can't express; `/a/**/:n(\d+)?/:y?` on `/a/x/1/1`: `[n]` beats `[n, y]`, which beats `[]`): the regex matches the same paths and takes another of the routes (the `OTHER_EXPANSION` capture class); exact captures would need an alternation of every route with duplicate names. A group right after a bare `**` (`/a/**{.json}?`) expands instead of inlining (`inlineOptionalGroup` compared the base with a lazy full form). A lone `:y?` after `**` / `:x*` (or a `*` after `:x*`, optional in the route without `x`) nests the catch-all in one optional group, `(?:/(?:(?<_>[\s\S]*)/)?(?<y>[^/]*))?`, which `parseLevel`'s `SEPARATOR_GROUP` head rule gives a closed ending; a lazy `**` / `:x*` followed by optionals only ends in a plain `/?$` (`openTail`: the catch-all absorbs a stripped slash, and being lazy leaves it to the `/?`), with the optionals after it rebuilt by `openOptionals()` (`_trailing-slash.ts`, `openEnding`'s rule: those that can be empty are lazy, so `/a/**/:y?/:z?` leaves `z` unset on `/a/b/` instead of capturing the stripped slash as `""`), unless the segment before the catch-all can be empty (case 6 above); a required catch-all before optionals keeps the look-behind (case 5 above). An inline `{…}?` after the catch-all passes its segments as `extra` so both halves pick the same laziness. Existing routes compile byte-identically (checked over the whole corpus). Perf (Node 24, 64 KB paths, µs): `/api/**` 14 (282 on a trailing-slash run); `/**/_payload.json` / `/api/**/_payload.json` 14 on a match, 91-156 on a near miss (repeated `_payload.json` segments), 140-284 on a slash run; `/**/:file`, `/a/**/:page?`, `/a/:x*/*` 14; `/api/**:p/x` 56; the lazy forms `/api/**/:n(\d+)?` 360-590 and `/api/**:r/:y?` (look-behind) ~900 — all linear (64K/4K ≈ 16).
- **Router-order expansion (`needsModifierExpansion`):** an empty segment followed only by optional ones (`/docs/{v2}?/:page?` → `/docs//:page?` also registers `/docs`, the empty segment turning trailing) expands through the router's own `expandModifiers`, _after_ group expansion like `addRoute` (a mid-route `:x+` / `:x*` used to as well; it is a catch-all with segments after it now, see above). `inlineOptionalGroup` bails on such routes (it used to feed the unexpanded prefix to the emitter: `/api/:p+/meta{.json}?` missed `/api/secret`). Identical branch sources are deduped before joining.
- A root-level optional is emitted as `(?:/X)?` with no leading `/`: `routeToRegExpSegments` returns `[segments, ownSeparator, starStar]` and `joinSegments` drops the leading `/` on that flag (an in-band sentinel char collided with literal route content, e.g. a NUL). The old `^\/?X` form let the leading slash double as a trailing one.
- **Not modeled:** constraints that can match `/` (`:x(.+)`, `:x([^.]+)`) — the tree splits on `/` first, the regex doesn't, so `/a/:x(.+)` matches `/a/b/c` and `/a/b//` (`x: "b/"`, also on main), and `/a/:x(.+)/b` matches `/a/x/y/b`; a user `([\s\S]*)` constraint compiles to exactly the catch-all regex. Repeated constrained params (`:id(\d+)+` / `*`) — a router bug: `expandModifiers` drops the constraint in the tree while the regex keeps it (regex under-matches). The empty path `""` (the router treats it as `/`; the regex requires a leading `/` except in the root forms whose first segment is optional, `/**`, `/:x*`, `/:x?`, `/*`, which do agree, so `routeToRegExp("/")` rejects `""` while the router matches it). `normalize: true` lookups (`.`/`..` are resolved before matching — the regex sees the raw path). PCRE/Perl `$` also matches before a final `\n` (no `D` / `PCRE2_DOLLAR_ENDONLY`), so there every regex also matches `<path>\n` (an over-match only; in JS and RE2 `$` is the end of input, and JS has no `\z` to emit instead).

### Catch-all regex emission

The separator before a catch-all is **never** a bare optional `\/?` after a prefix: `^\/api\/?(?<_>.*)` matched `/apifoo`, and `.+` could capture the separator itself (`/base/**:p` on `/base/` gave `p="/"`). Now `/api/**` → `^\/api(?:\/(?<_>(?:[\s\S]*[^/])?\/*?))?\/?$` (zero or more segments; the group is unset on `/api`, where the router reports `""`, and `""` on `/api/`), `/base/**:p` → `^\/base\/(?:\/|(?<p>(?:[\s\S]*[^/]|\/)\/*?)\/?)$`, and root `/:x+` / `/**:x` → `^\/(?:\/|(?<x>(?:[\s\S]*[^/]|\/)\/*?)\/?)$`. Only root `/**` keeps `^\/?` before its group (`^\/?(?<_>(?:[\s\S]*[^/])?\/*?)\/?$`, no prefix to overrun). Side effect for `regExpToRoute`: `**:name` and `:name+` emit **byte-identical** regexes (both one-or-more segments, `compareRoutes` → `equal`, same node key), so `**:name` reverses to `:name+`. A trailing greedy `(?:\/(?<_>…))?` reverses to `**`, the lazy `(?:\/(?<_>…))??` to `:_*` (the router leaves `:_*` unset on `/a/`, where `**` reports `""`, so the two no longer share output). Source round-trip still holds. `_regexp-cases.ts` fixtures carry `noMatch` paths asserted against the tree, the JS regex and every PCRE/RE2 engine — negative cases are what was missing when this shipped.

### RegExp → route (`regExpToRoute`)

- `src/regexp-to-route.ts` is the inverse of `routeToRegExp()`: it parses an anchored, PCRE-compatible `RegExp` (or its `source` string) back into a rou3 route pattern. Tree-shakeable — zero impact on the core bundle (only pulled in when imported).
- **Ending normalization is structural and exact-shape only.** After stripping `^`/`$`, the look-behind-free endings are rewritten back to a plain body + `\/?`: `ROOT_REPEAT` (a whole root `:x*`, returned directly), `plainBody()` for the closed endings (required `:x`, required catch-all, required `(.*)`, and tails after `REQUIRED_HEAD` `(?:(?<x>[^/]+)(?:\/|$)|\/)`, after an empty segment `\/\/`, or inside a `(?:\/(?:C)?)?` group, recursively), `TRAILING_CATCH_ALL` (`ANY_TAIL`, possibly inside `)?` / `)??` closers → `[\s\S]*`) and `TRAILING_DOT` (a lazy `(?:\/(?<x>.*?))??` → `.*`). Then the look-behind suffix, the pre-#209 two-slash suffix `(?:\/\/|(?<!\/)\/?)` or a plain `\/?` is stripped. There is no generic `.*?` rewrite, so a lazy quantifier the user wrote inside a constraint survives (`/a/:x(b.*?)`, `/a/pre-:x(.*?)`).
- The body walk recognizes static separators (`\/`) + segments, optional-group units `(?:…)?` and lazy `(?:…)??` (same paths), nested optional groups (these threw before, main included), and catch-alls: a greedy `(?:\/(?<_>[\s\S]*))?` → `**` (anywhere: segments may follow it now), the lazy group → `:_*` unless its body is lazy too (`[\s\S]*?`, a `**` before optional segments), a `\/(?<name>[\s\S]*)` (lazy body too) → `:name+` at the end or before more segments, root `\/?(?<_>…)` → `**` (also before more segments) / `\/?(?<x>…)` → `:x*` (was `/**:x`), and the nested `(?:\/(?:(?<x>[\s\S]*)\/)?(?<y>[^/]*))?` (`NESTED_CATCH_ALL`) → `**/:y?`, `:x*/:y?` or `:x*/*`. `[\s\S]*` is the catch-all body; `.*` (and `.+` for one-or-more) still reads as one, since released versions emitted it and the bytes are ambiguous with a `(.*)` constraint, unless the regex has a lazy user-`.` ending, in which case a whole `.*` is a constraint. So `/a/:x(.*)` now round-trips (main reversed it to `/a/:x+`). Segment-internal parsing maps `(?<name>[^/]*)` / legacy `(?<name>[^/]+)` → `:name`, optional `(?:\/(?<_N>[^/]*))?` → `*`, `(?<_N>[^/]*)` / bare `([^/]*)` → `*`, `(?<_N>pat)` / bare `(pat)` → `(pat)`, `(?<name>pat)` → `:name(pat)`, and re-escapes literal route-syntax chars (`: ( ) { } * \`). Bare (unnamed) capturing groups map like their `(?<_N>…)` counterparts.
- Optional units classify by inner shape: a whole-segment param → `:name?` / `:name*` / `:name(pat)?|*` (repeat form `pat(?:\/pat)*` → `+`/`*`); a whole-segment `:name?` / `*` with nested optionals → siblings at the root or inside a `{…}?` group (`/:x?/:y?` → itself), a merged `{/…}?` group after a segment (`/a/:x?/:y?` → `/a{/:x/:y?}?`, `/posts/:year/:month?/:day?` → `/posts/:year{/:month/:day?}?`, same routing); a literal/mixed inner → `{…}?` merged onto the previous segment (`(?:s)?` → `{s}?`, `(?:\/bar)?` → `{/bar}?`, `{/sub/**}?`). Whole-segment `.+` → `:name+`. Routes with identical output come back in one spelling: `/a{/**}?` → `/a/:_*`, `/a{/:w+}?` → `/a/:w*`.
- **Legacy inputs** (pinned in `test/regexp-to-route.test.ts`, "accepts catch-all regexes emitted by older versions" and the 9 main + 7 0.9.x table): main's look-behind suffix with `.*` catch-alls, the pre-#209 two-slash suffix, and 0.9.x's plain `\/?` ending with `\/?(?<_>.*)` / `\/?(?<name>.+)` catch-alls (→ `**` / `**:name`) and `[^/]+` params.
- **Known non-equivalences** (`KNOWN_NON_EQUIVALENT`, stale-guarded): a user `([\s\S]*)` constraint comes back as a catch-all (`/:x([\s\S]*)` → `/:x+`, `/a/:x([\s\S]*)?` → `/a/:x*`); `/a/:x?/*`, `/a/:x?/**`, `/:x/:y?/**`, `/a/:x?/**/b`, `/a/:x?/:y(\d+)?`, `/a/**/:y?/:n(\d+)?` and `/a/**/:y?/:n(a|b)?` compile to the nested regex of their `{/:x/…}?` form and come back as it (same paths, captured like the regex, not like the original). A follow-up could emit lazy siblings `(?:/X)??(?:/Y)??` for a `*` or constrained later optional, which would capture like the router and remove these.
- **Pre-existing gaps (same on main):** 0.9.2's `(?:\/(?<w>.+))?` (from `/a{/:w+}?`) reverses to `/a/:w(.+)?`, not `:w*`; the doubly nested `(?:(?:\/(?<w>.*))?)?` (0.9.2's `/a{/:w*}?`, main's `/a/c{/:w*}?`) throws.
- **Reject-by-default (no silent corruption):** `reverseSegment()` is a whitelist parser — only named/bare groups, escaped-punctuation literals, and plain literal chars are accepted. Anything outside the dialect throws a `rou3:` error instead of being literalized into a wrong route: structural look-arounds (`(?=` `(?!` `(?<=` `(?<!`) and other `(?…)` group constructs, backreferences and metaclass escapes outside a constraint (`\k<x>`, `\1`, `\d`, `\w`, `\b`), and bare (unescaped) regex operators at segment level (`. ^ $ * + ? | [ ] { }`). Constraint bodies (`(…)`) stay **opaque** — arbitrary regex inside them (quantifiers, non-greedy, look-arounds, nested groups) is preserved verbatim. `constraint()` still rejects bodies containing `/` (unrepresentable after path splitting). Match-affecting **regexp flags** (`i`/`m`/`s`) throw (routes carry none, so honoring them silently is impossible); `g`/`y`/`u`/`v`/`d` don't affect a fully-anchored match and are ignored.
- **Round-trip:** `routeToRegExp(regExpToRoute(regexp)).source === regexp.source` holds for every non-fallback fixture, and the reversed route must also route like the original (source equality alone let `/path/:rest*` come back as `/path/:rest(.*?)?`); `test/regexp-to-route.test.ts` asserts both over `_regexp-cases.ts` and the sweep corpus. The **alternation fallback** forms (`PCRE2_DUPLICATE_NAME_ROUTES`, e.g. `/media/*{.webp}?` → `^(?:…|…)$`) are not reversible and throw.

### Pattern overlap & subsumption (`routesOverlap` / `compareRoutes` / `findOverlappingRoutes`)

- The feature is tree-shakeable (the core bundle is unaffected; see `test/bench/bundle.test.ts`): `src/_overlap.ts` holds the shape model, `src/_subsume.ts` the subsumption/canonicalization layer, `src/operations/overlap.ts` the public API + tree traversal. A route is modeled as a `RouteShape`: an array of fixed single-segment matchers (`string` literal | `RegExp` constraint | `undefined` = any) plus a variable-length tail `[tailMin, tailMax]` (trailing `*` -> `[0,1]`, `**` -> `[0,∞]`, `**:name` -> `[1,∞]`, none -> `[0,0]`). The tail matches any values, so it constrains only segment **count**, never contents. Segments after a `**` form `suffix`: fixed matchers aligned to the **end** of the path (`/**/_payload.json` -> `[] [0,∞] ["_payload.json"]`); leading any-value suffix matchers fold into the tail like trailing fixed ones (`/**/:x/b` ≡ `/**:x/b`, `/**/:x` ≡ `/**:x`, so an all-any suffix disappears). With a suffix on either side, `shapesOverlap`/`shapeSubsumes` check each path length position by position (`matcherAt`) up to `stableLength` = max fixed + max suffix (past it the constrained positions stop moving relative to each other, so it stands for all longer lengths); `mergeShapes` also requires identical suffixes. `findOverlappingRoutes` walks suffix tries (`visitSuffixTrie`) after the bare `**` entries, without pruning inside them. Pinned by `overlap.test.ts` "segments after `**`", incl. a sweep of 29 patterns × every path ≤ 5 segments: 0 wrong claims and, without regex constraints, exact verdicts.
- Shapes are built from radix-tree entries (`shapeOf`): kind-tagged edges (static key | param | wildcard) plus the entry's own `paramsMap`. Carrying the node kind keeps escaped-literal static keys (`\*` -> static `"*"`) distinguishable from dynamic segments. Per-entry shapes are cached in a `WeakMap`.
- Query patterns are inserted into a throwaway router via the real `addRoute` (`routeToShapes`), so queries and registered routes are classified by the exact same pipeline (`expandGroupDelimiters` -> `encodeEscapes`/`splitPath` -> `expandModifiers` -> regex params). A pattern with optional/group syntax yields several shapes; patterns overlap when **any** shape pair overlaps. `routeToShapes` memoizes per pattern string (bounded `Map`, reset at 1024 entries) — pairwise consumers (`compareRoutes` over N patterns) pay N parses, not N²; callers must treat returned shapes as immutable.
- `shapesOverlap()`: check the shared fixed prefix then test that total-length ranges `[fixed+tailMin, fixed+tailMax]` intersect. Value check is length-independent because any valid common length ≥ `max(fixedA, fixedB)`.
- **Overlap = "∃ concrete path matched by both,"** not subset containment. `static`/`static` and `static`/`regex` are precise; `any`-vs-anything and `regex`/`regex` are **over-approximated to overlap** (conservative default — regex intersection is undecidable).
- **Shape canonicalization:** `_computeShape` (`_overlap.ts`) folds trailing `undefined` (any-value) fixed matchers into the tail (`/a/:x` -> `["a"] [1,1]`), and `routeToShapes` merges shapes with *identical* fixed prefixes (`_segmentEqual` — strict identity, never mutual-subsumption proofs) and contiguous length ranges (`/a/:x?` -> `["a"] [0,0]` + `["a"] [1,1]` -> `["a"] [0,1]`) via `mergeShapes` (`_subsume.ts`). Both are match-set-preserving; they make containment see through optional-syntax expansion (`/a/:x?` == `/a/*`).
- `compareRoutes(a, b)` classifies match-set relations: `disjoint` | `equal` | `superset` (strict unless equality is undecidable) | `subset` | `partial` (no containment proven, sets *may* intersect). Verdict names follow the ES2025 Set methods (`isSupersetOf`/`isSubsetOf`/`isDisjointFrom`); `superset`/`subset` are directional (`compareRoutes(a, b) === "superset"` means `a` ⊇ `b`). Built on `shapeSubsumes()` (`_subsume.ts`): `b`'s total-length range inside `a`'s + per-position matcher containment (`any` ⊇ all; literals by equality; anchored regex ⊇ literal via `test()`; regex ⊇ regex only by source equality modulo named-group names — `_regExpKey` strips `(?<name>` so param names never affect the verdict, `/u/:id(\d+)` == `/u/:x(\d+)`) + `a`'s fixed positions under `b`'s tail must be `any`. Pattern-level containment is proven shape-by-shape (each `b` shape inside a *single* `a` shape) — sufficient, not necessary, so union-split coverage degrades to `partial`. **Containment claims are proofs; undecidable directions degrade to a weaker verdict, never a wrong claim.** Two caveats are inherent: strictness of `subsumes`/`subsumed` is best-effort (an actually-equal pair whose equality is only provable one way — `/u/:id(42)` vs `/u/42` — reports the proven containment, not `equal`), and `partial`'s intersection half is over-approximated (a `partial` regex-vs-regex pair may in fact be disjoint). Both are pinned in `test/overlap.test.ts`.
- `findOverlappingRoutes` traverses the tree in `findAllRoutes` order (wildcard, param, static, self) so results are least→most specific, prunes static subtrees the query can't reach, and collapses only genuine reference-duplicates (a route with optional/group syntax expands into several entries sharing one `data` reference); distinct routes with equal-or-absent primitive `data` are all reported. Matches carry `data` only (a scope has no single concrete path → no `params`).

### Route node keys (`routeNodeKeys`)

`src/route-node-keys.ts` exposes the **radix-node identity** of a pattern — a syntactic tree property, deliberately separate from the semantic match-set relations `compareRoutes` answers. Tree-shakeable: it only reuses `createRouter`/`addRoute` (already in the core bundle) and is dropped entirely when unimported, so `test/bench/bundle.test.ts` is unaffected (measured byte-identical with and without the `src/index.ts` re-export).

- **Why it exists:** rou3 buckets registrations by **node**, and lookup resolves a node with `methods[method] || methods[""]`, so a method-scoped entry on a node hides that node's method-agnostic (`""`) entry. Consumers that bucket their own per-route metadata by **pattern text** (h3 PR #1524 did) see `/users/*` and `GET /users/:id` as two entries where rou3 has one bucket — the `basicAuth` gate is silently deleted, fail-open. `compareRoutes` cannot close this gap: over 18,336 pattern pairs, `=== "equal"` had 13% recall on node collisions and 51 of 338 `"equal"` verdicts did not collide (`/a/:x/**` vs `/a/:x+` are equal but live on `/a/*/**` and `/a/**`). Keep the two APIs separate.
- **Soundness contract:** `routeNodeKeys(A) ∩ routeNodeKeys(B) ≠ ∅` **⟺** A and B share a radix node (hence one `methods[]` bucket). Sound in **both** directions *as a statement about nodes*, and explicitly **not** a statement about match sets — the key erases regex constraints and widens `**:name` → `**`, so `/u/:id(\d+)` and `/u/:slug([a-z]+)` share `/u/*` while matching disjoint paths. Over-merging is the fail-closed direction and the correct bias here. It is **not** named `canonicalRoutePattern` for exactly that reason: the key is not an equivalent pattern.
- **Implementation constraint (non-negotiable):** never write a second pattern parser. `routeNodeKeys` inserts into a throwaway router via the real `addRoute` (exactly like `routeToShapes` in `_overlap.ts`) and DFS-walks the tree emitting `prefix || "/"` at every node with `methods` — which dedupes for free. A parser that drifts from `addRoute` would report node identities the router doesn't use, recreating the very bug this exists to prevent. It must **not** import `_overlap.ts` (that pulls `mergeShapes` from `_subsume.ts` into the graph).
- **Node-identity rules the key encodes:** param edge (`node.param`, key `*`) is taken by `:name`, `*`, `:id(\d+)`, `(\d+)` and mid-segment captures (`*.png`, `pre-:id-suf`, `file-*-*.png`) — name and constraint live in the *entry*, not the node; wildcard edge (`node.wildcard`, key `**`) by `**`, `**:rest`, `:x+`; segments after it live in the wildcard's suffix trie and key in route order (`/a/**:r/b` → `/a/**/b`, `/**.md` → `/**/*`); static otherwise via `decodeEscaped` with `\*`→`*` and `\*\*`→`**`. Trailing empty segments are all popped (`/a` ≡ `/a/` ≡ `/a//`, #193) but *middle* empties are a real static `""` key (`/a//b`).
- **Key encoding:** segments joined by `/`; param → `*`, wildcard → `**`, static key `k` emitted with `*`→`\*`, `**`→`\*\*` and `: ( ) { }` backslash-escaped, so a literal can never be read as a marker and every key is itself a route pattern reaching exactly its own node (`routeNodeKeys(k) === [k]`). Weaker encodings fail: escaping only `\`/`*` breaks idempotence (a static key may legitimately contain a raw `\`, e.g. `a\*`), and leaving `)`/`}` unescaped breaks it for keys like `\)`.
- **Memo:** bounded `Map` cleared at 1024 entries (same policy as `routeToShapes`); returns `keys.slice()` so callers cannot mutate the memo.
- **Tests (`test/route-node-keys.test.ts`) — the property sweep is what keeps this honest.** Over a 155-pattern corpus (segment alphabet × depth ≤ 2 × tails, plus optional/group/escape/suffix extras) it asserts `keysIntersect(a,b) === sharesNode(a,b)` for all 24,025 ordered pairs against ground truth read off the tree (0 mismatches). The **security** sweep then takes every disjoint-key pair (14,839), registers A under `""` and B under `GET`, and asserts A still comes back from `findAllRoutes` **and** compiled `matchAll` on every path A covers alone — 66,333 checks, 0 shadowed. A false negative in the key model surfaces there as a dropped `""` entry. Encoding injectivity is brute-forced over the adversarial alphabet `{a \ * : ( ) { } .}` up to length 3 (820 segments, 247 reachable static keys, 0 collisions, `*`/`**` reserved), plus idempotence and an explicit **non-goal guard** that equal keys do not imply equal (or overlapping) match sets.

### Capture-group name escaping

Param names accept `[\w-]+`, but a named capture group must be a valid identifier (no `-`, no leading digit) in JS **and** in PCRE. `src/_group-names.ts` is the codec every regex-emitting path goes through:

- `toGroupName()` passes valid identifiers through unchanged (the common case, so existing output is byte-identical) and escapes the rest behind `ESCAPED_GROUP_PREFIX` (`__rou3_esc_`), encoding `_` -> `__` and `-` -> `_h` (`:test-id` -> `__rou3_esc_test_hid`, `:0` -> `__rou3_esc_0`). Names in the reserved `__rou3_` space and `_N`-shaped ones (the unnamed form `routeToRegExp` emits) are escaped too, so a group name maps back to exactly one param name. The escape is a **prefix code** — every `_` in the output opens a two-char escape — hence injective: distinct names can't collide and decoding is exact. This is the whole point of the two-char `-` escape; the tempting `-` -> `_` sanitize is **not** injective (`a--b` decodes back as `a_b`, and `a-_b`/`a_-b` collide onto one group name, which is a duplicate-group `SyntaxError` at registration). Pinned by `test/group-names.test.ts`, which brute-forces round-trip + injectivity over an adversarial alphabet. The output stays within `[A-Za-z0-9_]`, so it is a legal PCRE group name (pinned by `regexp.pcre.test.ts` via the shared fixtures).
- `fromGroupName()` is the inverse and also strips `UNNAMED_GROUP_PREFIX`; it is the single read-back point (`getMatchParams` in `operations/_utils.ts`, the compiler's `scanRegExpGroups` path, and `matchNamedGroup` in `regexp-to-route.ts`). Params therefore always surface under the **original** route name (`params["test-id"]`), and `regExpToRoute()` restores `:test-id` rather than leaking the escaped form.
- Emission sites: `getParamRegexp()` (`operations/add.ts`) and all four in `regexp.ts` (plain, mixed-segment, `:name?`/`+`/`*` modifier, `**:name`). Before this, any param with `-` or a leading digit threw `SyntaxError: Invalid capture group name` from `addRoute()`/`routeToRegExp()` as soon as it appeared in a regex-compiled position — whole-segment `:test-id` worked only because it stores the name as a plain string key (#8dfaa48 widened the name class to `[\w-]` but left group emission raw). Pinned in `find.test.ts` "param names that are not valid capture-group names" and the `_regexp-cases.ts` fixtures.
- The compiler emits `.groups.<name>` property accesses, which are only valid because every emitted name is now an identifier; its runtime `_normalizeGroups` fallback (used when `scanRegExpGroups` can't parse a name, e.g. a unicode group inside a constraint body) inlines a copy of the same decode and must stay in sync with `fromGroupName()`.
- Known (pre-existing) ambiguity, unrelated to the escape: unnamed captures key on `"0"`, `"1"`, … , so a route that mixes a digit-named param with an unnamed capture (`/w/:0/*`) has two params claiming key `"0"` and the later one wins. Same on `main` before the escape existed — the numeric unnamed-key space simply overlaps digit-only param names.
- **Duplicate param names:** `routeToRegExpSegments` tracks the param names of each expansion (`groupName()`) and throws `rou3: duplicate param name "x" in "<route>"` on a repeat: `/files/:path/**:path`, `/a/:x/:x?`, `/a/:x.:x`, `/a/:x{/b/:x}?` (the message quotes the expanded route, `/a/:x/b/:x`), and a bare `**` counts as `_` (`/a/:_/**`). A duplicate named group compiles on some engines and not on others: the look-behind-free `**:x` / `:x+` ending puts one copy inside an alternative, which V8 (Node 24) accepts while Bun, Deno, PCRE2 and RE2 reject it, so every runtime now gets the same error (these routes threw a raw `SyntaxError` from `new RegExp` on main). The check is per expansion: the alternation fallback may still repeat a name across branches (`/media/*{.webp}?`, `/a/:x*/:x`); generated unnamed captures (`_N`) are never checked and can't collide (`:0` escapes to `__rou3_esc_0`); named groups inside a constraint body (`:x((?<y>a))`) are not tracked. The router differs: across segments the later value wins (`/u/:id/:id` on `/u/a/b` → `{ id: "b" }`), and within one mixed segment `addRoute` throws a raw `SyntaxError` (`getParamRegexp`), so `routeToRegExp` rejects some routes the router accepts. Pinned in `regexp.test.ts` "routeToRegExp: duplicate param names".

### Input path normalization

`normalizePath()` in `_utils.ts` resolves `.` and `..` segments in lookup paths (fast-path: skip if no `/.` found). Both `findRoute()` and `findAllRoutes()` normalize before matching. The compiler inlines equivalent logic in generated code.

### Empty segments (trailing vs middle)

Two different rules, and they must not be conflated:

- **Trailing** empties are canonicalized away at **registration**: `add`/`remove` split patterns with `splitRoute()` (`splitPath()` + pop *all* remaining trailing empties), so `/a//` ≡ `/a/` ≡ `/a` (#193). A single-pop split (the pre-#209 `splitPath()`) used to leave `/a//` as segments `["a", ""]` — the radix tree then matched only `/a///`, the `ctx.static` key was `/a/`, and the compiled static dispatch stripped to `/a`: three matchers, three answers. This mirrors the trailing-slash policy already documented for routes (`/a` ≡ `/a/`). Pinned in `find.test.ts` "route patterns with trailing empty segments (#193)".
- **Lookup paths** ignore **at most one** trailing slash (#209, breaking vs ≤0.9.x which ignored two): `findRoute`/`findAllRoutes` slice one trailing `/`, and `splitPath` keeps every remaining segment, so `/a/` reaches a `/a` route but `/a//` does not (a real empty last segment remains, which only a param/wildcard takes: `/a//` → `/a/:x` with `x: ""`). This matches Express/find-my-way/Hono non-strict defaults. The old rule (slice one **and** pop one trailing empty) stacked two tolerances and forced every matcher that must agree with the router (#200) to reproduce it. Do **not** reintroduce a pop in `splitPath` or the compiled prologue. Pinned in `find.test.ts` "at most one trailing slash is ignored (#209)".
- **Middle** empties are *meaningful* and preserved everywhere: `/a//b` is a static segment `""` in the tree and matches only the doubled-slash path, never `/a/b` (request paths keep their empty segments too, so collapsing would create the classic normalization-mismatch bypass; URLPattern also treats `//` literally). `routeToRegExpSegments()` used to `continue` on every empty segment, so `routeToRegExp("/a//b")` emitted `^\/a\/b\/?$` — matching the one path the router won't and missing the one it will. It now splits with `splitRoute()` and re-emits middle empties. Pinned by the `/path//sub` + `/path//:id` fixtures in `_regexp-cases.ts` (which assert tree and regex agree) and `find.test.ts` "routes with an empty middle segment".
- An empty segment directly before a wildcard (`/a//**`, `/a//*`, `/a//**:x`) agrees between regex and tree (covered by the `regexp.test.ts` property sweep).

### Wildcard segment captures

- **Breaking change:** unnamed captures now use URLPattern-style numeric keys (`"0"`, `"1"`, ...) instead of legacy `_0`, `_1`, ...
- Unescaped `*` inside a segment is treated as an unnamed capture (`"0"`, `"1"`, ...), including mid-pattern forms like `/*.png` and `/file-*-*.png`.
- Wildcard capture indexing is shared with unnamed regex groups in the same route.
- `removeRoute()` now treats wildcard-segment patterns as dynamic segments (same classification as add/find/regexp).

## Testing

- **Framework:** Vitest (config in `vitest.config.mjs`)
- **Dual validation:** Tests compare `findRoute()` results against `compileRouter()` output
- **Snapshots:** Tree structure and compiled code snapshots
- **Type tests:** `vitest typecheck` via `types.test-d.ts`
- Run a single test: `pnpm vitest run test/<file>.test.ts`
- **WPT compat tests:** `test/wpt.test.ts` validates URLPattern compatibility using Web Platform Test data. Known diffs are tracked in `KNOWN_DIFFS`, `REGEXP_ONLY_KNOWN_DIFFS`, and `ROUTER_KNOWN_DIFFS` sets with reason comments.
- **routeToRegExp fixtures (`test/_regexp-cases.ts`):** each `match` entry is `[path, groups?, params?]`. `groups` lists **every** named group of the regex exactly (`toStrictEqual`, unset = `undefined`, `_N` keyed as `"N"`, escaped names decoded); `params` is the `findRoute` result where it differs from `groups` (asserted to differ, so an override can't go stale), and router params are compared exactly (unset dropped). `noMatch` paths are asserted against the tree, the JS regex and every engine. `LOOKBEHIND_ROUTES` (4 fixtures) is asserted both ways; `PCRE2_DUPLICATE_NAME_ROUTES` (2) too.
- **Router-vs-regex sweeps (`test/regexp.test.ts`):** `sweepPatterns()` (355 patterns: a segment alphabet × tails at depth ≤ 2, nested-group, look-behind and segments-after-`**` shapes, plus every fixture, minus the routes `addRoute` rejects: a second `**`) × `sweepPaths()` (590 paths: up to 3 segments from `a`, `b`, `1`, `x.png` and empty, each with 0-3 trailing slashes, plus line terminators alone, at either end of a segment, mid-path and last). "matches exactly the paths findRoute matches" must report no mismatch. "captures what findRoute captures" accepts only the required-segment gap (`isRequiredSegmentGap`, see "Regex ≡ router"); anything else must be in `KNOWN_CAPTURE_DIFFS` (58 patterns in 3 classes, each with its own `test()`: a `**` matching zero segments is unset in the regex and `""` in the router (`/a/**` on `/a`, `/a/**/b` on `/a/b`: 22 of them have segments after the `**`; at the root the regex captures `""`); an optional param takes the segment the router gives a later `*` or constrained optional (`/a/:x?/*` on `/a/b`); several optionals after a catch-all, or a `:x*` expansion, take another of the routes the pattern registers (`OTHER_EXPANSION`: the regex's captures must be the params one of them gives the path, checked by routing it on its own)), and a listed pattern that no longer differs fails the stale guard. "pins the sweep patterns RE2 engines reject" asserts `SWEEP_LOOKBEHIND_PATTERNS` (18) and `SWEEP_DUPLICATE_NAME_PATTERNS` (21) exactly, without ripgrep, so a change that moves routes onto the look-behind or into a duplicate-name alternation fails loudly. Smaller sweeps cover line terminators in catch-alls, slash-capable constraints (at most one segment + one trailing slash), JS character-class tokenizing, a param named `_` vs `**`, the duplicate-name throws, and the second-`**` throws (`TWO_CATCH_ALL_ROUTES`, the same error as `addRoute`).
- **Reversal equivalence (`test/regexp-to-route.test.ts`):** every non-fallback fixture must round-trip by source **and** route like the original over the sweep paths (plus the same paths under the route's static prefix); every sweep pattern must reverse to a route that routes the same, except `KNOWN_NON_EQUIVALENT` (10 entries, stale-guarded: each must still come back as the listed route and still differ), and only alternation output may throw. A table pins 9 main + 7 0.9.x legacy regexes and the routes they reverse to.
- **PCRE cross-engine tests:** `test/regexp.pcre.test.ts` runs `routeToRegExp()` output through whichever real PCRE-compatible CLIs are installed (`grep -P`, `rg -P`, `pcre2grep`, `pcregrep`, `perl`, `php`). Each candidate is included only after a `(?<name>...)` sanity probe, so missing/non-PCRE tools are auto-skipped (suite is a no-op if none are present). All fixtures are asserted to compile and match on every detected engine. Engines that see the input whole (`perl`, `php`) check every fixture path; the line-based ones (`grep -P`, `rg -P`, `pcre2grep`, `pcregrep`, and ripgrep below) skip inputs containing `\n`. `PCRE2_DUPLICATE_NAME_ROUTES` flags any route whose output reuses a named group across alternation branches (valid in JS/Perl, rejected by PCRE2 without `PCRE2_DUPNAMES`); it contains the non-inlinable cases (`/media/*{.webp}?`, a mid-segment optional after a greedy capture, and `/docs/{v2}?/:page?`) — for those the suite asserts strict PCRE2 engines _reject_ the output while Perl accepts and matches it. `test/regexp.test.ts` asserts every other fixture emits no duplicate named groups, and conversely that each `PCRE2_DUPLICATE_NAME_ROUTES` entry really does (so the set can't go silently stale).
- **RE2 cross-engine tests:** a second suite runs ripgrep's default engine (the Rust `regex` crate, an RE2-family engine: no look-around, no duplicate names) through the `ripgrep` devDependency: ripgrep compiled to WASM (no PCRE2), called in-process via `ripgrep(args, { buffer: true })` with the input lines in a temp file, so it needs no system binary and never skips (~2 ms per call). A first test proves the engine (named groups match, a look-behind fails to compile); `--no-config` keeps a user config from switching engines and `--text` keeps a NUL from triggering binary detection. Fixtures outside `LOOKBEHIND_ROUTES` / `PCRE2_DUPLICATE_NAME_ROUTES` must compile and match (those two must be rejected). Every sweep pattern outside `SWEEP_LOOKBEHIND_PATTERNS` / `SWEEP_DUPLICATE_NAME_PATTERNS` must match the same paths as JS (one run per pattern, the sweep paths without a `\n` as input lines), and the pinned ones must fail to compile. The package also puts its WASM `rg` on the PATH of package scripts, so the PCRE suite's `rg -P` candidate spawns with `node_modules` dirs filtered out of `PATH` (`systemEnv`) to reach a system build; otherwise its probe fails and it silently drops out.

## Best Practices

### Code Style

- Prefer ESM over CommonJS
- Use explicit extensions (`.ts`/`.js`) in import statements
- For `.json` imports, use `with { "type": "json" }`
- Avoid barrel files (`index.ts` re-exports); import directly from specific modules
- Place non-exported/internal helpers at the end of the file
- For multi-arg functions, use an options object as the second parameter for extensibility
- Split logic across files; avoid long single-file modules (>200 LoC). Use `_*` for naming internal files

### Bug Fix Workflow (Regression-First)

1. **Write the regression test first** — reproduce the exact bug
2. **Run it and confirm it fails** — MUST fail before touching implementation
3. **Fix the implementation** — minimal change
4. **Run the test again** — confirm it passes
5. **Run the broader test suite** — ensure no regressions

Never skip step 2. A regression test that wasn't proven to fail first has no value.

### Git

- **Commits:** Semantic, lower-case (e.g., `perf: ...`, `fix(compiler): ...`), include scope, add short description on second line
- If not on `main`, also `git push` after committing
- Use `gh` CLI for GitHub operations
