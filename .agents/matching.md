# Matching

## Tree

Node kinds: **static**, **param** (key `*`: `:id`, `:id(\d+)`, mixed segments like `:a-:b`, and the segment-local pieces of a `*` inside a segment, see [below](#greedy-)), **wildcard** (key `**`, the catch-alls: `**`, `**:rest`, `:x+`, `:x*`, a whole-segment `*`, `(.*)` or `:x(.*)`). Names and constraints live in the `MethodData` entry, not the node. Non-obvious `Node` fields:

- `suffix` (on a wildcard node): trie of the segments after `**`, stored **last segment first**. A separate field so forward walkers never read it as children.
- `hasSuffix`, `hasRegexParam`: pruning flags, never cleared on removal (cost only).

Lookup priority: static > param > wildcard, except on paths a suffix route matches (below).

**Results** are fresh `{ data, params? }` objects, never the stored `MethodData` (one shared object per route). Static matches and `params: false` have no `params` key; interpreter params are null-proto. An absent optional param (`:x?`, `:x*`, `{…}?`) has no key (the expansion without it matched), nor does an absent in-place one (`*-:x?`: its group is unset, `getMatchParams` skips `undefined`). Not so a trailing optional `*` that takes no segment: its key stays, `undefined` (`/a/*` on `/a` gives `{"0": undefined}`), and a bare `**` gives `_: ""`. `addRoute` stores `data ?? null`, so falsy data round-trips.

Guard `index < segments.length` before any `node.static[...]` lookup: `undefined` must never coerce to the key `"undefined"`.

## Same-node siblings

Several entries in one node's `methods[method]` resolve by one model in all three matchers (`_selectMatcher` in `find.ts`, `pushSorted` in `find-all.ts`, `collectSuffix` in a suffix trie, the compiler): the highest weight among **fully matching** entries wins, ties go to the first-registered. Weight = +2 per passing regex param, plus, for a required last param, +2 (`:name`, `**:name`, `:x+`, `:x*`'s `**:x`), or +1 for a `*`. Siblings differ there only on a wildcard node, `**` (0) < `*` (1) < `**:name` (2), and a `**` with a regex param ties a `**:name` (2 = 2) as it always did (routers without a `*` order as before). A trailing `*` matches the paths a `**` does (`compareRoutes`: `equal`), so its point only breaks that tie, and stays below a regex param (`/p/:x/*` ⊋ `/p/:x(\d+)/**` on one wildcard node: 1 < 2); `/a/*` ⊋ `/a/**:x` (1 < 2). The same order in a suffix trie (`collectSuffix`, scaled by two: see [below](#segments-after-a-catch-all)), where a `*` needs a segment. Elsewhere every entry gets the same, so the interpreter adds it everywhere and the compiler counts its conditions, ×4 (presence guards, a non-empty guard included, don't count), +2 for a `*`, and in a suffix trie a `plain` regex counts +1 instead of a condition (`starWeight`). A failing regex skips the entry (fall through to less specific siblings/nodes), never aborts. Absolute weights may differ per node by a constant, but the order must match. Keep `_selectMatcher`'s single-sibling/no-regex fast path.

## Method-agnostic (`""`) entries

A node's `methods[""]` entries compete with `methods[method]` in one pool: highest weight wins; on equal weight the method-scoped entry wins (`findRoute`) / comes after the `""` one (`findAllRoutes`, compiled matchAll); then registration order. A `""` lookup sees `methods[""]` only.

Never resolve a node with `methods[method] || methods[""]`: it hides `""` entries when the method one fails to match (a fail-open for guards registered method-agnostic, e.g. h3 `use()` middleware). Specificity-first is the rule across nodes and in `rankFromEnd` too, and keeps the ordering contract.

Implementation: `methodEntries()` (`operations/_utils.ts`) feeds `_findAll`/`pushSorted`, `collectSuffix`, `_collectEntries` (overlap); `_selectMatcher` walks the method list then the `""` list with a strict `>`; the compiler emits, inside each `if(m==="X")`, X's matchers plus the `""` ones weight-sorted together, and keeps an `else{""}` block. Tests: `test/method-agnostic.test.ts`.

## `findAllRoutes` ordering (public contract)

Least → most specific; interpreter and compiled matchAll agree exactly (`toEqual`).

- Across node kinds: traversal order wildcard → param → static → self.
- Same-node siblings: weight ascending, stable on ties, `""` before the method's on ties.
- Compiler: matchers sorted **descending**, emitted as `r.push(...)`, one `return r.reverse()`. In matchAll the matcher list is pre-reversed so ties keep insertion order; single-match must **not** pre-reverse (first `return` wins = first-registered).
- On paths a suffix route matches: re-sorted by `rankFromEnd`.

**Carve-out (known, do not "fix"):** tree entries are ordered, but `compareRoutes` compares whole patterns. A multi-expansion pattern (`:x?`, `:x*`, `{…}?`) can be the broader one only via an expansion that does not take part in the match, so no node-local weight can see it. Classes, pinned in `find-all.test.ts` ("optional-syntax carve-out") and README:

- **A1** identical expansion, registration order decides (`/admin` vs `/admin/:page?`).
- **A2** same node, the matched entry is narrower. No instance `compareRoutes` proves: a `:x*` needs a value, so `/api/:v/:path*` is a `subset` of `/api/:v/**` (`/api/v//`), which the order agrees with; the test pins that.
- **A3** different nodes, traversal decides (`/p/:id{/**}?` and `/p/:id/*`: on `/p/a/` its `/p/:id` entry comes after the `*` child). No strict instance now that a trailing `*` is optional (the two match the same paths, `equal`); the test pins the order.

A3 can't be fixed by weights; a real fix is a global re-sort against `compareRoutes` (major design change).

**Carve-out B (known, do not "fix"):** every segment of a `**:name` (`:x+`, `:x*`) needs a value, so a route with a `:name` and a `*` / `**` over its segments contains it (`/p/:x/**` ⊋ `/p/:x+`, `/**/:y/p` ⊋ `/**:n/p`, `/:a/**/p` ⊋ `/**:n/p`: the broader one also takes the paths with an empty segment there). The traversal lists a node's wildcard before its param child, and a suffix trie's shallower entry first (`collectSuffix`, ties in `rankFromEnd`), so the narrower route comes first and `findRoute` picks the broader one. Pinned in `find-all.test.ts` ("catch-all carve-out (B)") and README; the same fix as A3. It is the price of URLPattern's `:x+`: with empty segments inside the value (before 0.12) the two were incomparable.

Swept by "lists a containing route before a contained one (sweep)" in `find-all.test.ts` (`*` included, both registration orders, compiled JIT/AOT and `findRoute` too): a pattern-level miss passes only as a carve-out where no matched entry of the broader pattern is itself strictly broader than one of the narrower listed before it, and every carve-out there is A1 (an entry of the narrower pattern listed before one of the broader with the same match set), or where each such pair is B (`catchAllFirst`: the narrower entry's `**:name`, a `:name` of the broader one from where it starts and a bare catch-all; `suffix.test.ts`' sweep reads the same on patterns). Blind spot: `compareRoutes` says `partial` for in-place optionals (`:a:b?`) and constraints that take any non-empty segment (`(.+)`), so the sweep can't see their order. It uses one method: the `""`-first tie rule would break its both-orders reading with mixed methods.

## Greedy `*`

A `*` is URLPattern's `*`, a greedy `(.*)` after its `/`: a catch-all. One per route, like `**`, `:x+`, `:x*` (`/*/x/*`, `/*/**`, `/file-*-*.png` throw `oneCatchAll`; adjacent `**` inside a segment is the misplaced-modifier error).

- **Whole segment:** `segmentKey` sends a `*` to the wildcard node, entry `[-(i + 1), "N", false, true]` (the 4th slot, `empty`: it may capture `""`, unlike `**:name`; a `:name(.*)` has its name there, see below). It takes one segment or more, empty ones included; where it ends the route, or one of its expansions (before optional segments or groups: `/a/*/:x?` and `/a/*{.png}?` match `/a`, `/a{/b/*}?` `/a/b`), also none, as the route without it (as in 0.11, unlike URLPattern, so `use("/api/*")` scopes cover `/api`): `matchesZero()` (`_utils.ts`; true for every wildcard entry but a `**:name`). It then matches the paths a trailing `**` does; the stripped trailing slash only decides its capture: `getMatchParams(…, slash)` skips a bare `**` over zero segments, and a `*` there unless the path had the slash (`/a/*`: `{}` on `/a`, `""` on `/a/`; the root `/` always has it). `findRoute` / `findAllRoutes` pass `slash` to `getMatchParams` only, the compiler reads `t` (see [compiler.md](compiler.md#codegen-invariants)). Before more of the route it is a catch-all with a suffix like `**` (below), ≥ 1 segment. Param nodes hold no optional entry any more: no end-of-path param fallback.
- **Inside a segment:** `splitStar()` (`_utils.ts`, shared by `_add` and `removeRoute`, after `expandModifiers`) reads `pre*post` as the segment-local pieces around a `**`: `pre*`, `**`, `*post` (where the capture spans segments) plus the segment as is (where it doesn't: two entries, `expandedRouteId` identity); `*post` alone as `**`, `*post`; `pre*` as `pre*`, `**` (a `**` that needs a segment, at the end of the route and before more of it, so the two never match the same path: `matchesZero`, the compiler and overlap skip a trailing `join` one) plus the segment as is, ranked on its param node like `pre*post`'s (`/blog-*` beats `/:slug` on `/blog-post`). The pieces are one capture: the `**` (5th `paramsMap` slot, `join`, no `_` alias) and the `*post` piece reuse the `*`'s local number (`_insert`'s `head`/`join`), and `getMatchParams` (`setParam`) / the compiler (`prop`, `pieces`) join their values with `/` (the `**`'s only where it has a segment). Sound because the route has no other catch-all: the capture starts at its segment's `pre` and ends at the last segment's `post`, and the one-segment and spanning routes differ in segment count. `getParamRegexp` emits a piece's `*` as an unnamed group `([^/]*)`, numbered left to right with unnamed constraint groups.
- **No zero segments for a `*` inside a segment:** `/a/*:x?` and `/a/*(\d*)` don't match `/a/` (URLPattern: `{ 0: "" }`), like `/a/(\d*)`, nor `/a`: the `*post` piece is a segment that must exist, and only the whole-segment entry is optional. Extending that to a nullable `*post` would need a zero-segment branch in both walks, the suffix trie, the compiler and the regex for a corner case, so it is documented instead (README differences table); `/a//` matches.
- `splitRoute()` reads a `**<rest>` segment (rest not starting with `:`, `{`, `}`, `*`) as `*<rest>`, so `/**.md` ≡ `/*.md` everywhere (one capture, as in URLPattern); `***` is `**` + `*` (two catch-alls).
- **`(.*)` and `:name(.*)`** are a `*`, as in URLPattern (where `*` and `(.*)` are one token). `starGroups()` (`_utils.ts`) rewrites them before anything else reads the pattern (`addRoute` after `checkConstraints`, `removeRoute`, `routeToRegExp` after its `addRoute` validation; derived APIs go through `addRoute`), so the tree, compiler, regex, overlap and `routeNodeKeys` see a `*` and need no case of their own. Details:
  - A `:name(.*)` keeps its name through the `unnamed` map it returns (`Unnamed` returns a number or that name): its `*` takes an unnamed index in the rewritten route, and the later ones shift down, so `/:p(.*)/(\d+)` keys `p` and `0`. The entry is a `*`'s, named (`[-(i + 1), "p", false, true]`): every reader tells a `*` by `empty` (slot 3), never by a digit name (`matchesZero`, `emptyParam`, the compiler's trailing-`*` check, `shapeOf`), so it is optional at the end, may be `""` and weighs like a `*`. `_insert` declares the name once per route (`captureKey`; the pieces of a split `*` share it), so a repeat throws before a regex is built; groups name it through `toUnnamedGroupKey` (`toGroupName` for a name). Its registration identity is `expandedRouteId` of the pattern as written, so `/a/*` doesn't remove `/a/:p(.*)` (an unnamed `(.*)` is `*`'s identity: either removes the other).
  - Where a `*` would read as a modifier or a `**` (right after a `:name`, a group or a `*`, or where a group's `{` / `}` may put it there), it is written after U+FFFF (`/:x(\d+)(.*)` is `/:x(\d+)\uFFFF*`, `/{:foo}(.*)` `/{:foo}\uFFFF*`). `joinGroup` keeps the U+FFFF only after a `:name`, group or `*` and drops it elsewhere (`/{a}?(.*)` is `/a*` or `/*`); `getParamRegexp` keeps it through the name replace (so `:foo` takes no `(` after it as its constraint) and then drops it. After a `*` it leaves a second catch-all (`*\uFFFF*`, `oneCatchAll`). The U+FFFF stays in a registration identity (consistent: add and remove rewrite alike). `checkConstraints` runs first, so a pattern can't write one.
  - Modifiers: `(.*)*` / `:name(.*)*` are left alone and throw as before (`)*`, a constrained `:x*`); `(.*)?` / `(.*)+` / `:name(.*)?` become `*?` / `*+` and throw like those (`:name(.*)?` was an optional one-segment constraint). Escapes are pairs (`\(.*)` is a literal `(.` + `*` + `)`); a `(.*)` can't sit in another group (`checkConstraints` rejects a capture there, also in a class: `:x([(.*)])`), so no depth tracking. Other constraints that can match `/` (`(.+)`, `(.*?)`, `([^x]*)`) stay segment-scoped: the regex over-matches them ([regexp.md](regexp.md)).
  - Types: `ExtractWildcards` makes a `(.*)` right after a `/` that ends the route (also before a last `{…}?`, `EndingStar`) optional like a `*`; `ParamAt` does the same for a `:name(.*)` that starts its segment.

## Segments after a catch-all

Segments after a `**` (or a `*`) match from the **end** of the path; the catch-all takes what is between (≥ 0 segments for `**`, ≥ 1 for `*`, ≥ 1 for `**:name`, each with a value). Mid-route `:x+` / `:x*` become `**:x` and keep the segments after them.

- **Syntax:** one catch-all per route (`*`, `**`, `:x+`, `:x*`); `_add` throws `rou3: a route can have only one ...` quoting the input as written (threaded through expansion as `input`).
- **Params:** `MethodData.suffix = [wildcard index w, suffix length n]`; a param at route index `k` after the `**` maps to `index - w - 1 + (n - k)` at match time (`getMatchParams`, `collectSuffix`, compiled `s[l-j]`). A bare `**` between them over zero segments is unset (see [Unnamed captures](#unnamed-captures)).
- **Ranking** (`rankFromEnd`, `operations/_suffix.ts`): when a suffix route matches (`hasSuffixMatch`, pruned by `hasSuffix`), `findRoute` collects all matches (`_findAll(…, reverse = true)`) and stable-sorts comparing from the last segment backwards: literal 3 > regex param 2 > plain param or `**`-covered 0 (a plain param must be 0, or `/**/:y` beats the narrower `/b/**`; so must a regex that restricts no more, `paramsMap`'s `plain`: `:a:b?`, `*:x?`). `kindAt` returns a covered segment as `~start` of its `**`, so comparisons jump over ranges both `**` cover (cost ∝ segments around the `**`, not path length). Ties keep tree order; `reverse` makes the last match the first-registered. `findAllRoutes` applies the same sort when a suffix route is among its matches. Paths no suffix route matches are untouched. Known (README): the from-end ranking also applies between non-suffix routes on those paths. Pinned by the `suffix.test.ts` sweep "never picks a strictly broader route".
- **Within a suffix trie** (`collectSuffix`): shallower first, then param child, then static child; same-node entries by weight (+ 4 per passing regex, + 1 for a capture-only one, `plain`, which restricts no more than a `:name` but must not tie one; + 2 for a `*`, + 4 for a `**:name`: `/*/:y` beats `/**/:a:b?`, a `**` with a regex ties a `**:name` as on main), ties insertion order.
- **Compiler:** see [compiler.md](compiler.md#suffix-routes).

## Removal

`removeRoute` splices entries by the registration identity `_add` stamps on them (`MethodData.route`), never the whole bucket, so same-node siblings survive.

- Plain pattern: identity = the rewritten segment join (static keys via `segmentKey`, dynamic segments as written, suffix included), the same string `ctx.static` is keyed by. Spellings the tree can't distinguish remove each other (`/a/` ≡ `/a`, `\)` ≡ `)`, `/**.md` ≡ `/*.md`, `/café-:id` ≡ `/caf%C3%A9-:id`). A `*` inside a segment is removed through the same `splitStar` routes.
- Identities are compared canonically (`routeId`: each segment through `dynamicKey`, which percent-encodes a dynamic segment's literal text like `getParamRegexp`, outside constraints, `?{}` kept as syntax, and is a no-op on a static key), in `removeRoute` and `findOverlappingRoutes`' dedupe, so both spellings alias; a constraint is regex and stays distinct (`:x(é)` vs `:x(%C3%A9)`). Escapes are not canonicalized (`/:x-a` vs `/:x-\a` stay distinct): a missed alias, never a wrong one. The canonical form is computed where identities are compared, not stamped by `addRoute`, so the core bundle (routers that never remove) doesn't carry it.
- Expanding pattern (groups, modifiers): every entry gets the pre-expansion text normalized by `expandedRouteId()` (static segments via `segmentKey`), so the `/admin` entry of `/admin/:page?` never collides with a separately registered `/admin`. A group that expands to a single route (`/a/*-{:x}?` is `/a/*-:x?`, `/a{b}` is `/ab`) is that route: it takes the rewritten route's identity (both `_add` and `_removeRoute` skip `expandedRouteId` there). `expandGroupDelimiters` returns that rewrite alone, also next to another group, so the next group is expanded from the rewritten text: its identity is `expandedRouteId` of `/*-:x?/b{.json}?` for `/*-{:x}?/b{.json}?` too, and `skipGroup` renumbers the right group (`/a/*{:x}?/b{/(\d+)}?/(\w+)` on `/a/q/b/z` is `{0:"q", 2:"z"}`, as in URLPattern). A pattern starting with a group (no `/` in front, see [syntax.md](syntax.md#leading-)) is read after a `/` (the split drops a path's first piece) and marked with a leading `{`: read after a `/`, `{a}?/b` is the text of `/{a}?/b`, and both register `/a/b`. A malformed `{…` removes nothing.
- All entries with that identity go (duplicates together). An emptied static node deletes its `ctx.static` key via the join accumulated during the walk (no value scan).
- Removal is by registered pattern: `/x/*` does not remove `/x/:id`; `:id(\d+)` and `:x(\d+)` are distinct.
- Suffix routes: `_removeSuffix` walks back from the last segment, prunes empty trie nodes, then `wildcard.suffix`, then the wildcard (`_isEmptyNode` counts `suffix`).

## Empty segments and normalization

- **Pattern** trailing empties: `splitRoute()` pops all of them (`/a//` ≡ `/a/` ≡ `/a`).
- **Lookup** paths: at most **one** trailing `/` is ignored and `splitPath` keeps every other segment, so `/a//` has an empty last segment that only a `*`, `**` or a constraint takes (`0: ""`). Do not add a pop to `splitPath` or the compiled prologue; the regexp and compiler rely on this rule.
- **`:name` / `**:name` need a value, in every segment** (URLPattern's `:x+` is `[^/]+(?:/[^/]+)*`): `emptyParam()` (`operations/_utils.ts`) rejects an entry that gives a `:name` an empty segment, or a `**:name` an empty one anywhere in its value (it reads the value `getMatchParams` gives: `""`, or a leading, trailing or doubled `/`), at the end of the route and before more of it (a suffix route). It tells them apart in `paramsMap`: a `*` (also a `:name(.*)`: a `*` keyed by name, any segment of which may be empty) is `empty`, a bare `**` is digit-named (no param name starts with a digit), a constraint is a RegExp and decides itself (`:id(\d*)` takes `""`, as in URLPattern). `:name+`, `:name*`, `:name?` and `{/:x}?` follow from their expansions: `:x+` is `**:x`, `:x*` is `**:x` plus the route without it (`{/:x+}?`), so on `/a//` or `/a/b//c` a `/a/:x*` falls through like a `/a/:x+` (URLPattern: no match), and still matches `/a`. A user-written `**:name` is the same entry as `:name+`, so it follows the same rule (its docs say it needs a value; one rule, no second flag). One ignored trailing slash still applies: `/a/:x+` on `/a/b/` is `x: "b"`. With it, `/p/:x/**` ⊋ `/p/:x+` (carve-out B above).
  - Interpreter: `findRoute` sends paths with an empty segment (`segments.includes("")`, rare) through `_findRanked` (`find-all.ts`: `findAllRoutes`' walk, filtered by `emptyParam`, ranked from the end when a suffix route is among them), whose last match is `_lookupTree`'s pick (same traversal, weights and ties), so `_lookupTree` / `_selectMatcher` / `collectSuffix` never check. Paths without one pay a single `includes("")`; paths with one take this slower path (~2× in `findRoute`: it collects every match, so its cost is bounded by the matches found).
  - Compiler: see [compiler.md](compiler.md#codegen-invariants). Pinned by the "empty segments (compiled parity, sweep)" in `find.test.ts`.
- **Middle** empties are real static `""` segments: `/a//b` matches only the doubled-slash path. Never collapse them (normalization-mismatch bypass).
- `normalizePath()` resolves `.` / `..` before matching (skipped when no `/.`); the compiler inlines the same logic. A last `.` / `..` leaves a trailing slash, as in WHATWG (`/foo/bar/..` → `/foo/`): a trailing `*` reads it (`""`).
- **Percent-encoding:** lookup paths are the encoded pathname (`new URL().pathname`) and are never decoded; a route's literal text is encoded at insert instead (see [syntax.md](syntax.md#percent-encoding)). Do not add decoding to the hot path.

## Unnamed captures

An unescaped `*` (`/*`, `/*.png`, `/file-*`), a bare `**` and an unnamed regex group are unnamed captures keyed `"0"`, `"1"`, … in pattern order over the **whole pattern** (URLPattern, which reads `**` as `*` with a `*` modifier): `/(\d+)/x/**` gives `0` and `1`, `/(\d+)-*` gives the group `0` and the `*` `1`, and the pieces a `*` inside a segment is split into share its key (`/**.md` is `/*.md`: one `0`). A left-out optional group uses up the numbers of its captures (`/a{/(\d+)}?/**` keys the `**` `1` on `/a/x/y` too), so a capture has one key in every route a pattern registers (`findAllRoutes` and the regex can't disagree per expansion). `_add` counts a route's captures (`_unnamedParamIndex`, also through `getParamRegexp`, and returns the count) and maps each through `unnamed` (identity for a plain pattern); for the expansion without a `{…}?` group, `skipGroup()` (`add.ts`) shifts the captures after it by the group's count, which `_add` itself counts on the text before the group with and without its body, joined like `expandGroupDelimiters` (`joinGroup`: in `/:a{(\d+)}?/*` the group holds an unnamed `(\d+)`, so the `*` is `1` in both routes; no second parser). Early bails keep plain groups at their old cost: a pattern without `*` / `(` skips `skipGroup`, and a group body without them (not extending a catch-all) skips the counting. `routeToRegExp` threads the same `unnamed` (`toRegExp` → `inlineOptionalGroup` / `routeToRegExpSegments`, emitting `_N`), so both expansions of an inline group line up. Modifier expansions drop no unnamed capture. A param name can't collide with them (a name can't start with a digit; `:_0` is the key `_0`).

**Deprecated `_` alias** (0.x compatibility): the router also reports a bare `**` capture as `_`. `getMatchParams` sets it next to the numbered key (`index < 0 && optional && !join` is only a bare `**`, not the one a `*` inside a segment is split around); the compiler writes the tail once into the temp `_w` (`"N":_w=tail,_:_w`, declared with the regex temps when `ctx.starStarTemp`), so routes without a bare `**` pay nothing. `_add` records `_` as a taken name for a bare `**` (`addName`), so `/:_/**` and `/**/:_` throw a duplicate name. Types add `_?: string` with `@deprecated` (`DoubleStarAlias`). `routeToRegExp` keeps only the `_N` group (no regex can capture one group under two names); tests comparing router params with regex groups or URLPattern drop the alias (`routerCaptures` in `regexp.test.ts`, `withoutAlias` in `test/_utils.ts`, which also accepts a split `*`'s key without it).

A bare `**` over **zero segments** is unset, its key left out (not `undefined`; both keys), as in URLPattern (`/a/**` on `/a`, `/a/**/b` on `/a/b`); one empty segment is `""` (`/a//`). Since one trailing slash is ignored, `/a/` and the root `/` on `/**` are zero segments too (URLPattern: `""`). `getMatchParams` skips an `optional` entry when `~index >= end` (`~index` is a catch-all's start, negative for other params); the compiler emits `l>c ? {…, "N": tail} : {…}` (`compileFinalMatch`, `suffixGuard` for suffix routes); the regex leaves the group unset (a lazy optional group, at the root too: `(?:/(?<_0>…))??`). A trailing `*` over zero segments is unset too, but `""` after a trailing slash (see [Greedy `*`](#greedy-)): the regex gives it a greedy optional group.
