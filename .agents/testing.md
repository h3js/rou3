# Testing

- `pnpm test` runs lint, `tsc`, and vitest with coverage; one file: `pnpm vitest run test/<file>.test.ts`. Type tests: `test/types.test-d.ts`.
- Matcher tests compare `findRoute` / `findAllRoutes` with compiled JIT and AOT output; tree and codegen are snapshot-tested.
- `test/star.test.ts`: the greedy `*` against URLPattern (a table of shapes, with `differs` where rou3 ignores a trailing slash, run in every matcher and `routeToRegExp`; a sweep over patterns × paths that also checks captures), two-catch-all errors, `*` / `**` / `:x` / static priority and ordering, and `compareRoutes` / `routeNodeKeys` cases.
- Paths with empty segments (`/a//`, `/a//b`, `/a/b//c`) must be in every sweep: a `:name` / `**:name` can't take one (anywhere in a `**:name`'s value) while `*` / `**` can (`sweepPaths()`, the `overlap.test.ts` / `suffix.test.ts` alphabets hold `""`, and `find.test.ts` "empty segments (compiled parity, sweep)" compares interpreter and compiled on random routers).
- Brute-force sweeps (pairs of patterns × short paths) back the hard invariants: `find-all.test.ts` (containing route listed first, see [matching.md](matching.md#findallroutes-ordering-public-contract)), `suffix.test.ts` (never pick a strictly broader route), `method-agnostic.test.ts`, `overlap.test.ts`, `route-node-keys.test.ts`, `regexp.test.ts`, `regexp-to-route.test.ts`. Keep them passing with 0 violations; known exceptions live in named, stale-guarded sets (a listed entry that stops differing fails).
- `test/wpt.test.ts`: URLPattern WPT data, vendored verbatim (to sync, copy upstream's `urlpattern/resources/urlpatterntestdata.json` and update the SHA in the file header). Read like WPT's runner (`urlpatterntests.js`): `expected_obj: "error"` must throw `rou3:` (except `ACCEPTED_INVALID_PATTERNS`), `baseURL` / URL-string inputs resolve to their pathname, every input is percent-encoded like `new URL().pathname` (`encodePathname`, checked against the runtime's URLPattern in `PERCENT_ENCODING_CASES`), and entries that are not a lone `pathname` pattern are counted as out of scope. Groups compare with `toStrictEqual` (`null` in the data = an unset group = `undefined`); the one modelled difference is `expectedGroups()`: the tree leaves an unset param out of `params`, so for tree strategies an unset URLPattern group ≡ an absent key (a present `undefined` param still differs). Diffs live in `KNOWN_DIFFS`, `REGEXP_ONLY_KNOWN_DIFFS`, `ROUTER_KNOWN_DIFFS`: maps from label to rou3's exact result (groups, `null` for no match; `split(regexp, router)` where the regex and the tree also differ), each asserted to differ from URLPattern **and** to equal the stored result, so a behaviour PR that changes a listed case must update its entry. Rejected syntax is in `RESERVED_PATTERNS` (asserted to throw); an entry the data no longer reaches fails. Each skip names its reason and checks the exact entry shape that reason describes (anything else throws `wpt: unexpected …`); `--reporter=verbose` prints per-strategy counts. Where the runtime has a global `URLPattern` (not Node 22), "agrees with the runtime's URLPattern" checks every in-scope, non-skipped case (the resolved input, groups as read) against it, as do the `EMPTY_SEGMENT_CASES` / `PERCENT_ENCODING_CASES` / `GROUP_PARAM_CASES` / `LEADING_GROUP_CASES` side tables (with `LEADING_GROUP_DIFFS`: where rou3 matches and URLPattern doesn't; empty segments have no diff left).

## Regex fixtures and sweeps

- **Fixtures** (`test/_regexp-cases.ts`): `match` entries are `[path, groups?, params?]`. `groups` lists every named group exactly (`toStrictEqual`, unset = `undefined`, `_N` keyed `"N"`, escaped names decoded); `params` is the `findRoute` result where it differs (asserted to differ). `noMatch` paths are asserted against the tree, the JS regex and every engine. Pinned sets: `LOOKBEHIND_ROUTES`, `PCRE2_DUPLICATE_NAME_ROUTES`, `LOOKAHEAD_ROUTES`, `RESERVED_SYNTAX_ROUTES`, `TWO_CATCH_ALL_ROUTES`.
- **Sweeps** (`regexp.test.ts`): `sweepPatterns()` × `sweepPaths()` (rejected routes dropped via `routerAccepts`). "matches exactly the paths findRoute matches" must report nothing. Escapes have their own pattern × path sweep ("reads escapes like findRoute": the generic sweeps have no `\x`), and "over-matches only for constraints that can match `/`" pins the one exception's direction. "captures what findRoute captures" accepts no difference outside `KNOWN_CAPTURE_DIFFS` (classes: an optional taking a later optional's segment; `OTHER_EXPANSION`). `SWEEP_LOOKBEHIND_PATTERNS`, `SWEEP_LOOKAHEAD_PATTERNS`, `SWEEP_DUPLICATE_NAME_PATTERNS` are asserted exactly, so moving a route onto a look-behind or alternation fails loudly.
- **Reversal** (`regexp-to-route.test.ts`): every non-fallback fixture round-trips by source and routes like the original; every sweep pattern reverses to an equivalent route except `KNOWN_NON_EQUIVALENT`.

## Cross-engine

- **PCRE** (`regexp.pcre.test.ts`): runs output through installed `grep -P`, `rg -P`, `pcre2grep`, `pcregrep`, `perl`, `php` (each probed first, auto-skipped when missing; line-based tools skip inputs with `\n`). `PCRE2_DUPLICATE_NAME_ROUTES` must be rejected by strict PCRE2 and accepted by Perl. `rg -P` spawns with `node_modules` dirs removed from `PATH` (`systemEnv`) so it reaches a system build, not the WASM one.
- **RE2 family**: the `ripgrep` devDependency (WASM, Rust `regex` engine, no system binary needed) via `ripgrep(args, { buffer: true })` with `--no-config --text`. Everything outside the look-behind / look-ahead / duplicate-name sets must compile and match like JS; those sets must fail to compile.
- **Node 22** (no duplicate named groups): tests gate on the `DUPLICATE_NAMED_GROUPS` probe in `_regexp-cases.ts` (fixtures and sweep patterns needing it are dropped, `unsupportedSweepPatterns()` must equal `SWEEP_DUPLICATE_NAME_PATTERNS`). CI has a `node22` job. Locally, `pnpm` may pick its own Node, so run `node node_modules/vitest/vitest.mjs run` with the Node 22 binary. Node 20 (the `engines` floor) is not tested (vitest needs 22.12+).
